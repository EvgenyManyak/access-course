## 1. Быстрый старт

Если вы уверенно работаете за компьютером и хотите начать немедленно:

1. Убедитесь, что стоит **Microsoft Access 2007–2016** на Windows (проверка: Файл → Учётная запись → «О Access»).
2. Создайте папки `C:\Courses\ShopData\` с подпапками `import\`, `base\`, `export\`, `backup\`.
3. Скопируйте в `import\` шесть CSV из каталога [`starter-data/`](../starter-data/) репозитория: categories, products, customers, employees, orders, order-details.
4. Откройте Access → «Пустая база данных» → имя `ShopData.accdb` → сохраните в `base\`.
5. Импортируйте шесть файлов (порядок: categories → products → customers → employees → orders → order-details) — процедура и таблица типов в [разделе 6](#6-импорт).
6. Задайте первичные ключи (если не задали в мастере) и пять связей — [раздел 7](#7-типы-ключи-связи).
7. Выполните тестовый запрос `SELECT TOP 5 …` из [раздела 8](#8-первый-запрос) и сверьте эталон.
8. Сделайте копию базы в `backup\` и открывайте [модуль 01](../modules/01-access-basics.html).

Время: 30–40 минут. Kaggle, регистрация и скачивание больших датасетов на этом шаге не нужны.

## 2. Полная установка

### 2.1 Операционная система

Подходит Windows 7 SP1 (для Access 2010–2013), Windows 8.1, 10, 11. Курс показан на Windows 10/11 + Access 2016. Проверка версии Windows: **Win+R → `winver` → Enter**.

### 2.2 Microsoft Access

| Вариант | Подходит? | Примечание |
|---|---|---|
| Access 2016 / Office 2016 Professional (Plus) | ✅ | Показан в учебнике |
| Access 2013, 2010, 2007 | ✅ | Отличия интерфейса описаны в модулях |
| Microsoft 365 (десктопные приложения) | ✅ | Лента почти не отличается от 2016 |
| Access 2019+/2021 | ✅ с оговоркой | Интерфейс чуть новее; весь материал применим |
| Access Runtime | ❌ | Не позволяет создавать таблицы, запросы, формы |
| Access for Mac / Access Online | ❌ | Не существует |
| LibreOffice Base | ⚠️ | Похоже, но другой диалект SQL и мастера; задания курса сверяйте по Access |

Разрядность (32/64-бит) для курса не важна — главное, чтобы весь Office был одной разрядности. Учебная база — файл `.accdb` (формат 2007+); работать в режиме совместимости `.mdb` не нужно.

### 2.3 Excel и браузер

Excel 2007+ желателен: модуль 04 разбирает импорт XLSX, модуль 13 — экспорт. Для просмотра CSV достаточно Блокнота. Учебник читается в любом современном браузере без интернета: откройте `index.html` из распакованного репозитория или `standalone.html`.

## 3. Подготовка данных

### 3.1 Структура папок

```text
C:\Courses\ShopData\
├── import\    ← исходные CSV (стартовый комплект, позже — Olist)
├── base\      ← база ShopData.accdb и её учебные копии
├── export\    ← выгрузки XLSX/CSV/PDF (модули 11, 13)
└── backup\    ← резервные копии базы
```

Создать одной командой PowerShell:

```powershell
md C:\Courses\ShopData\import, C:\Courses\ShopData\base, C:\Courses\ShopData\export, C:\Courses\ShopData\backup
```

Требования к пути: без кириллицы и пробелов; не сетевой диск и не папка синхронизации (OneDrive/Google Drive) — Access чувствителен к блокировкам файлов при записи.

### 3.2 Стартовый комплект данных

Каталог [`starter-data/`](../starter-data/) — шесть файлов эталонного мини-датасета ShopData:

| Файл | Таблица | Строк | Ключ | Назначение |
|---|---|---|---|---|
| categories.csv | Categories | 5 | CategoryID | Категории товаров (португальское/английское имя) |
| products.csv | Products | 8 | ProductID | Товары: название, категория, цена, вес, габариты |
| customers.csv | Customers | 8 | CustomerID | Покупатели: имя, почтовый префикс, город, штат, сегмент |
| employees.csv | Employees | 6 | EmployeeID | Менеджеры заказов: роль, город, дата найма |
| orders.csv | Orders | 12 | OrderID | Заказы: покупатель, менеджер, статус, даты |
| order-details.csv | OrderDetails | 15 | OrderDetailID | Позиции заказов: товар, количество, цена, доставка |

Седьмая таблица курса — служебный календарь Calendar (761 дата) — создаётся в модуле 04 VBA-генератором [`vba/calendar-generator.bas`](../vba/calendar-generator.bas) или импортом [`datasets/calendar.csv`](../datasets/calendar.csv).

Формат всех файлов: UTF-8 с BOM, CRLF, разделитель — запятая, даты ISO (ГМД: `2017-03-15`), цены с точкой (`189.90`). Формат совпадает с большим датасетом Olist, поэтому одна настройка мастера подходит всем файлам.

### 3.3 Проверка целостности и кодировки

1. Сверьте размеры файлов (КБ): categories 0,2; products 0,6; customers 0,4; employees 0,5; orders 0,8; order-details 0,7; calendar 38. Нулевой размер — перекачайте.
2. Откройте customers.csv в Блокноте: вторая строка — `C-0001,Ana Ribeiro,01310,sao paulo,SP,Retail`; кириллица в products.csv («Набор постельного белья 2-сп») читается. Кракозябры → файл пересохранён не в UTF-8, скачайте заново.
3. Посчитайте строки PowerShell: `(Get-Content …\customers.csv).Count` → 9 (шапка + 8). Нормы: categories 6, products 9, customers 9, employees 7, orders 13, order-details 16, calendar 762.
4. Не пересохраняйте файлы из Excel — он может поменять кодировку и разделители.

### 3.4 Альтернатива — полный датасет Olist

Большой датасет (Kaggle Olist Brazilian E-commerce, ~100 тыс. заказов) подключается по инструкции [datasets/import-instructions.md](../datasets/import-instructions.md), путь А, начиная с модуля 04. Он не заменяет стартовый комплект: контрольные числа курса выверены на мини-датасете, а Olist хорош для упражнений на объёме (агрегаты, оптимизация).

## 4. Доверенная папка

Access блокирует макросы, VBA и часть мастеров для «недоверенных» файлов. Один раз добавьте папку курса:

1. Access → **Файл → Параметры → Центр управления безопасностью → Параметры центра управления безопасностью… → Доверенные расположения**.
2. **«Добавить новое расположение»** → укажите `C:\Courses\ShopData\` → ОК. Галочку «Разрешить расположения в сети» не включайте.
3. Если жёлтая полоса «Включить содержимое» ещё появляется — нажмите её (один раз для файла вне доверенной папки).
4. Проверка: откройте базу из `base\` — предупреждений быть не должно.

**Системные объекты** (MSys*) по умолчанию скрыты — курс не требует их показывать. Если понадобится: правый щелчок по заголовку области навигации → «Параметры навигации…» → «Показывать системные объекты». Содержимое MSys-таблиц не изменяйте и верните галочку после осмотра.

Не добавляйте в доверенные весь диск или «Загрузки» — доверенность означает «этому источнику я верю», а VBA умеет всё, что умеет любая программа.

## 5. Первая база

1. Access → «Пустая база данных».
2. Имя файла: `ShopData.accdb`.
3. Значок папки → `C:\Courses\ShopData\base\` → «Создать».
4. Появится «Таблица1» в режиме таблицы — закройте её без сохранения (правый щелчок по вкладке → Закрыть → Нет).
5. Область навигации должна показывать пустой список «Все объекты Access».

Все модули курса ссылаются на базу по имени `ShopData.accdb` — назовите её именно так, инструкции будут совпадать со скриншотами.

## 6. Импорт

### 6.1 Общая процедура (на примере categories.csv)

1. **Внешние данные → Новый источник данных → Из файла → Текстовый файл** → `import\categories.csv` → «Импортировать исходные данные в новую таблицу» → ОК.
2. «С разделителями» → Далее.
3. Разделитель — **запятая**; ограничитель — `"`; «Первая строка содержит названия полей» — включено.
4. **«Дополнительно…» → Порядок дат: ГМД** → ОК → Далее. (Без этого шага 2017-03-15 может распасться на текст или перепутанные месяцы.)
5. Проверьте превью по образцу из [starter-data/README.md](../starter-data/README.md) → Далее.
6. Назначьте типы полей (см. 6.2) → Далее.
7. «Самостоятельно задать первичный ключ» → выберите поле ключа → Далее.
8. Имя таблицы — по словарю курса → Готово. Окно «Сохранить шаги импорта» закройте.

Повторите для остальных файлов в порядке **categories → products → customers → employees → orders → order-details**.

### 6.2 Поля, типы, ключи по файлам

| Файл | Таблица | Ключ | Критичные типы |
|---|---|---|---|
| categories.csv | Categories | CategoryID | Оба имени — Короткий текст (64); CategoryID — Числовой |
| products.csv | Products | ProductID | UnitPrice — Денежный; WeightG — Числовой (длинное целое); LengthCm/HeightCm/WidthCm — Числовой (целое) |
| customers.csv | Customers | CustomerID | ZipCodePrefix — **Короткий текст (5)** (ведущий ноль!); Segment — текст (Retail/Wholesale/VIP) |
| employees.csv | Employees | EmployeeID | Role — текст (Менеджер/Оператор/Аналитик); HireDate — Дата/время; SellerID — текст |
| orders.csv | Orders | OrderID | OrderStatus — текст; три даты — Дата/время; пустые DeliveredDate — это NULL, так и нужно |
| order-details.csv | OrderDetails | OrderDetailID | Quantity — Числовой (целое); UnitPrice/FreightValue — Денежный; ShippingLimitDate — Дата/время |

Примечание о счётчиках: значения ключей 1–5, 1–6, 1–15 уже в файлах. Оставьте эти поля «Числовыми» с первичным ключом — задания курса этого достаточно. Тип «Счётчик» Access позволяет задать только на пустой таблице; если хотите строго повторить схему из модуля 02 — импортируйте структуру без данных и допишите строки, но практической разницы не будет.

### 6.3 Проверка импорта каждого файла

- Первая строка совпадает с образцом из [starter-data/README.md](../starter-data/README.md);
- Количество строк: 5 / 8 / 8 / 6 / 12 / 15 (счётчик внизу окна таблицы);
- ZipCodePrefix показывает 01310 (с нулём), цены выровнены вправо, даты — датами.

## 7. Типы, ключи, связи

### 7.1 Проверка типов

Конструктор каждой таблицы (правый щелчок → «Конструктор») → сверить колонку «Тип данных» с таблицей 6.2. Три типовых расхождения и лечение — в [разделе 10](#10-частые-ошибки) (даты, ведущий ноль, деньги как текст).

### 7.2 Первичные ключи

Значок ключа в конструкторе у каждого ключа из таблицы 6.2. Если нет: выделить строку поля → «Ключевое поле» → Ctrl+S. Тест: попытка ввести второй заказ `O-10001` в Orders должна отклоняться («повторяющиеся значения»), Esc отменяет.

### 7.3 Связи

**Работа с базами данных → Схема данных** → добавить все шесть таблиц. Пять связей (перетащить поле на поле, включить «Обеспечение целостности данных»):

| Связь | Поля | Особенности |
|---|---|---|
| Categories → Products | CategoryID → CategoryID | 1:М |
| Customers → Orders | CustomerID → CustomerID | 1:М |
| Employees → Orders | EmployeeID → ManagerID | 1:М |
| Orders → OrderDetails | OrderID → OrderID | 1:М + **каскадное удаление** |
| Products → OrderDetails | ProductID → ProductID | 1:М |

Шестая связь Calendar → Orders (CalDate = OrderDate) добавляется в модуле 04 после создания календаря. Теория связей — модуль 03.

### 7.4 Проверка ссылочной целостности

- В Orders введите ManagerID = 9 → Access отклоняет (нет сотрудника 9) → Esc.
- В OrderDetails введите OrderID = O-99999 → отклоняется → Esc.
- На схеме данных у линий стоят «1» и «∞».

## 8. Первый запрос

Создание → Конструктор запросов → закрыть окно добавления таблиц → правый щелчок по вкладке → «Режим SQL» → вставить и выполнить (кнопка «!»):

```sql
SELECT TOP 5 CustomerID, CustomerName, City, Segment
FROM Customers
ORDER BY CustomerID;
```

Эталон: пять строк C-0001 Ana Ribeiro … C-0005 Elena Costa. Сохраните запрос как `qry_КлиентыТоп5` (Ctrl+S) — это первый сохранённый объект курса.

Контрольные проверки базы:

| Запрос | Ожидание |
|---|---|
| `SELECT COUNT(*) FROM Orders;` | 12 |
| `SELECT COUNT(*) FROM OrderDetails;` | 15 |
| `SELECT SUM(UnitPrice) FROM Products;` | 1423.10 |
| `SELECT MAX(OrderDate) FROM Orders;` | 2018-06-12 |

Интеграционный тест — выручка по категориям без отменённых (эталон модуля 08):

```sql
SELECT c.CategoryNameEn,
       ROUND(SUM(od.UnitPrice * od.Quantity), 2) AS Выручка
FROM Categories AS c
INNER JOIN (Products AS p
            INNER JOIN (Orders AS o
                        INNER JOIN OrderDetails AS od
                        ON o.OrderID = od.OrderID)
            ON p.ProductID = od.ProductID)
ON c.CategoryID = p.CategoryID
WHERE o.OrderStatus <> "canceled"
GROUP BY c.CategoryNameEn
ORDER BY SUM(od.UnitPrice * od.Quantity) DESC;
```

Ожидание: bed_bath_table 769.50 · computers_accessories 746.50 · furniture_decor 640.00 · health_beauty 631.50 · automotivo 238.00, итого 3025.50. Сошлось — база полностью готова.

## 10. Частые ошибки

| # | Симптом | Причина | Решение |
|---|---|---|---|
| 1 | Кракозябры в превью мастера | Кодировка не UTF-8 | На шаге мастера выберите «Юникод (UTF-8)»; файл пересохраните только заново из репозитория |
| 2 | Даты текстом или день/месяц перепутаны | Не задан порядок дат | Переимпортируйте с «Дополнительно… → ГМД»; перед повторным импортом удалите кривую таблицу |
| 3 | ZipCodePrefix = 1310 (ноль потерян) | Поле стало числовым | Переимпорт с типом «Короткий текст (5)»; либо конструктор → текст + `UPDATE Customers SET ZipCodePrefix = Format([ZipCodePrefix],"00000")` |
| 4 | Цены текстом, SUM = 0 | Локальная запятая vs точка в CSV | Импорт как текст → новое денежное поле → `UPDATE Products SET НовоеПоле = CCur(Val([СтароеПоле]))`; или переимпорт с ручным типом «Денежный» |
| 5 | «Повторяющиеся значения» при установке ключа | Файл импортирован дважды | Удалить таблицу, импортировать один раз |
| 6 | «Не удалось найти входную таблицу OrderDetails» | Таблица названа order-details или не импортирована | Переименуйте таблицу (правый щелчок → Переименовать) в OrderDetails или доимпортируйте файл |
| 7 | «Нарушение целостности» при связи | Разные типы полей или сироты в данных | Сверьте типы по 6.2; импортируйте все шесть таблиц, потом стройте связи |
| 8 | Полоса «Включить содержимое» | База вне доверенной папки | Раздел 4 этой инструкции |
| 9 | Пусто в DeliveredDate у трёх заказов | Не ошибка | NULL у O-10005 (shipped), O-10006 (canceled), O-10010 (processing); проверка — `Is Null`, модуль 07 |
| 10 | Запрос из каталога sql/ не видит таблиц | База называется иначе, чем в инструкции | Имя базы свободное, но имена таблиц должны совпадать со словарём; проверьте, что работаете в импортированной базе |

## 11. Резервное копирование

- **Копия перед рискованными шагами** — action-запросы (модуль 08), каскадные удаления, разделение базы (модуль 14): закройте Access, скопируйте `base\ShopData.accdb` в `backup\ShopData_ГГГГ-ММ-ДД.accdb`.
- **Регулярная копия** — раз в неделю или после каждой учебной сессии.
- **Штатное средство** — Файл → Сохранить как → «База данных Access»; Access создаёт копию и переключается на неё. Для учебных целей копия Проводником удобнее.
- **Сжатие** — Файл → Сведения → «Сжать и восстановить»; автосжатие: Параметры → Текущая база данных → «Сжать при закрытии».
- Восстановление = возврат копии в `base\` под именем ShopData.accdb. Потерять можно только несохранённый ввод — Access пишет данные сразу.
