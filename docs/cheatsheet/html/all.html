DDL — создание и изменение структуры

CREATE TABLE · ALTER TABLE · DROP TABLE · первичный и внешний ключи (PK → FK)
В русской локали Access в выражениях часто используется ; вместо ,

CREATE TABLE создание таблицы

Создаёт новую таблицу: перечисляются поля, их типы данных и ключ.
Синтаксис
CREATE TABLE таблица (
  поле1 тип [PRIMARY KEY],
  поле2 тип, ...);
Пример — одна таблица
CREATE TABLE Products (
  ID AUTOINCREMENT PRIMARY KEY,
  ProductName TEXT(100),
  UnitPrice CURRENCY);
Результат: пустая таблица Products с ключевым полем ID, текстовым и денежным полями.

ALTER TABLE изменение структуры

Добавляет новое поле или меняет тип существующего — без пересоздания таблицы.
Синтаксис
ALTER TABLE таблица ADD COLUMN имя тип;
ALTER TABLE таблица ALTER COLUMN имя тип;
Пример — добавить поле
ALTER TABLE Products
  ADD COLUMN CategoryGroup TEXT(40);
Пример — расширить поле до 255 символов
ALTER TABLE Products
  ALTER COLUMN CategoryGroup TEXT(255);
Результат: у всех существующих записей новое поле равно Null, пока его не заполнят.

CREATE TABLE две связанные таблицы — PK → FK

Сначала создаётся таблица-справочник, затем таблица со ссылкой на её ключ: поле CategoryID в Products объявляется типом LONG и связывается ограничением FOREIGN KEY.
Пример — справочник и таблица товаров со связью
CREATE TABLE Categories (
  CategoryID AUTOINCREMENT PRIMARY KEY,
  CategoryName TEXT(60) NOT NULL);

CREATE TABLE Products (
  ProductID AUTOINCREMENT PRIMARY KEY,
  ProductName TEXT(100) NOT NULL,
  UnitPrice CURRENCY,
  CategoryID LONG,
  CONSTRAINT FK_Products_Categories
    FOREIGN KEY (CategoryID)
    REFERENCES Categories (CategoryID));
Результат: вставить в Products.CategoryID значение, которого нет в Categories, Access не даст — связь 1:∞ под защитой.

PK и FK — роль ключей

PKуникальный идентификатор записи своей таблицы
FKссылка на запись (PK) другой таблицы
NOT NULLполе обязательно для заполнения
UNIQUEзначения в столбце не повторяются

DROP TABLE удаление таблицы

Удаляет таблицу целиком — и структуру, и все данные. Действие необратимо.
Синтаксис
DROP TABLE таблица;
Пример
DROP TABLE Products;
Результат: таблица Products исчезает из схемы данных вместе со всеми записями.
Практика: если на таблицу ссылается связь FK, сначала снимите связь — и только затем выполняйте DROP TABLE.

NOT NULL · UNIQUE ограничения столбца

NOT NULL запрещает пустые значения, UNIQUE — повторы в столбце.
Пример — оба ограничения
CREATE TABLE Categories (
  CategoryID AUTOINCREMENT PRIMARY KEY,
  CategoryName TEXT(60) NOT NULL);
ALTER TABLE Categories
  ADD CONSTRAINT Uq_Name UNIQUE (CategoryName);
Результат: пустое имя категории и дубликат Access отклонит при вводе.
"Электроника"✓ принято
"Электроника" — повтор✗ UNIQUE
Null — пусто✗ NOT NULL

SELECT — выборка данных

выбор полей · DISTINCT · псевдонимы AS · сортировка ORDER BY · первые записи TOP
Фильтр строк делает WHERE — см. блок 4

SELECT * все поля

Звёздочка выбирает все столбцы таблицы — быстрый просмотр целиком.
Синтаксис
SELECT * FROM таблица;
Пример
SELECT * FROM Products;
Результат: все строки и все столбцы Products без фильтрации и сортировки.

SELECT отдельные поля

Перечисление столбцов через запятую оставляет только нужные поля — запрос быстрее и понятнее.
Синтаксис
SELECT поле1, поле2 FROM таблица;
Пример
SELECT ProductName, UnitPrice FROM Products;
Результат: два столбца ProductName и UnitPrice; столбец ID в вывод не попадает.

DISTINCT без повторов

Убирает дубликаты из результата: каждая комбинация значений выводится один раз.
Синтаксис
SELECT DISTINCT поле FROM таблица;
Пример
SELECT DISTINCT Category FROM Products;

AS псевдоним столбца

Задаёт заголовок столбца в результате — своё имя для поля или выражения.
Синтаксис
SELECT поле AS псевдоним FROM таблица;
Пример
SELECT ProductName AS Товар FROM Products;
Результат: данные те же, но столбец подписан «Товар» — удобно для выгрузок и отчётов.

ORDER BY сортировка

Сортирует результат: ASC — по возрастанию (по умолчанию), DESC — по убыванию.
Синтаксис
ORDER BY поле [ASC | DESC];
Пример — по убыванию цены
SELECT ProductName, UnitPrice
FROM Products ORDER BY UnitPrice DESC;

TOP первые записи

Возвращает заданное число первых строк — почти всегда вместе с ORDER BY, иначе строки непредсказуемы.
Синтаксис
SELECT TOP N поля FROM таблица ORDER BY ...;
Пример — топ-2 дорогих товара
SELECT TOP 2 ProductName, UnitPrice
FROM Products ORDER BY UnitPrice DESC;

Порядок частей запроса SELECT

Access выполняет части запроса именно в этом порядке: FROM находит таблицу → WHERE отбирает строки → GROUP BY группирует → HAVING фильтрует группы → ORDER BY сортирует → SELECT возвращает поля.

Условия отбора — WHERE

= · IN · BETWEEN · LIKE · IS NULL / IS NOT NULL · AND · OR · NOT — каждый оператор фильтрует строки по-своему

JOIN — объединение таблиц

INNER · LEFT · RIGHT · CROSS · SELF · имитация FULL OUTER через UNION — с мини-схемами связей
Условие соединения — ON; для читаемости задавайте псевдонимы AS

INNER JOIN только совпадения

В результат попадают только записи, у которых нашлась пара в другой таблице.
Пример
SELECT Products.ProductName,
       Categories.CategoryName
FROM Products INNER JOIN Categories
ON Products.CategoryID = Categories.ID;
Результат: товары, у которых заполнена категория; товар без пары пропадает.

LEFT JOIN все слева + совпадения

Все записи левой таблицы; для тех, у кого нет пары, поля правой заполняются Null.
Пример
SELECT Products.ProductName,
       Categories.CategoryName
FROM Products LEFT JOIN Categories
ON Products.CategoryID = Categories.ID;
Результат: весь список товаров, даже без категории (категория = Null).

RIGHT JOIN все справа + совпадения

Зеркально LEFT: все записи правой таблицы; без пары слева — Null в полях левой.
Пример
SELECT P.ProductName, C.CategoryName
FROM Products AS P RIGHT JOIN Categories AS C
  ON P.CategoryID = C.ID;
Результат: все категории, даже пустые — те, где нет ни одного товара.

CROSS JOIN каждая с каждой

Декартово произведение: каждая строка левой таблицы сочетается с каждой строкой правой. В Access — запятая вместо ключевого слова.
Пример
SELECT Count(*) FROM Products, Categories;
Результат: количество строк = строки Products × строки Categories (3 × 2 = 6).

SELF JOIN таблица с самой собой

Таблица соединяется с собой через два псевдонима — например, сотрудники и их руководители по полю ManagerID.
Пример — кто кому подчиняется
SELECT e1.EmployeeName AS Сотрудник,
       e2.EmployeeName AS Руководитель
FROM Employees AS e1 LEFT JOIN Employees AS e2
  ON e1.ManagerID = e2.EmployeeID;

Псевдонимы и связь по нескольким полям

Псевдонимы сокращают запись; если таблицы связываются по составному ключу — условия перечисляются через AND.
Соединение по одному полю (через псевдонимы)
FROM Products AS P INNER JOIN Categories AS C
ON P.CategoryID = C.ID
Соединение по нескольким полям — условия через AND
FROM T1 AS a INNER JOIN T2 AS b
ON a.Key1 = b.Key1 AND a.Key2 = b.Key2
Результат: обе части пары ключей должны совпасть одновременно — так соединяются таблицы со сложным ключом.

FULL OUTER JOIN в Access не поддерживается — имитация через UNION

Полное внешнее соединение (все записи обеих таблиц) напрямую недоступно. Его собирают из двух запросов: LEFT JOIN плюс RIGHT JOIN с условием IS NULL по ключу левой таблицы, объединёнными оператором UNION.
Схема имитации
SELECT P.ProductName, C.CategoryName
FROM Products AS P LEFT JOIN Categories AS C ON P.CategoryID = C.ID
UNION
SELECT P.ProductName, C.CategoryName
FROM Products AS P RIGHT JOIN Categories AS C ON P.CategoryID = C.ID
WHERE P.CategoryID IS NULL;

Преобразование типов и вычисления

Nz · IsNull · Val · CCur · CInt / CLng · CDate · Replace · IIf — схема «исходное значение → функция → результат»
В русской локали Access аргументы разделяются ;

Nz замена Null значением

Возвращает поле, а если оно Null — подставляет запасное значение. Спасает суммы и конкатенации.
Синтаксис и пример
Nz([UnitPrice]; 0)
Результат: Nz([UnitPrice];0)*1.2 посчитается даже там, где цена не заполнена.

IsNull проверка на Null

Возвращает Да/True, если поле пустое. В отличие от = Null работает всегда.
Синтаксис и пример
IsNull([CategoryGroup])
Результат: WHERE IsNull([CategoryGroup]) — то же, что WHERE CategoryGroup IS NULL.

Val извлечение числа из текста

Читает число из начала текстовой строки; запятую заранее меняют на точку через Replace.
Синтаксис и пример
Val(Replace([UnitPrice]; ","; "."))
Результат: текстовая цена стала числом — с ней работают сравнения и Sum/Avg.

CCur приведение к денежному типу

Превращает число или текст в денежное значение — убирает ошибки округления при расчётах.
Синтаксис и пример
CCur(Val([UnitPrice]))
Результат: значение готово для денежного поля и точных сумм в отчётах.

CInt · CLng целые числа

CInt — целое в диапазоне Integer, CLng — длинное целое для больших значений и ключей.
Синтаксис и пример
CInt([Quantity])    CLng([ID])
Результат: 12.7 → 13 (округление к чётному банкирское: 12.5 → 12).

CDate приведение к дате

Превращает текст или число в настоящую дату — после этого работают Year, DateAdd, DateDiff.
Синтаксис и пример
CDate("01.03.2024")
Результат: строка стала датой; в SQL литералы дат записываются между #.

Replace замена символов

Заменяет в строке все вхождения одной подстроки другой — чистка дефисов, разделителей, кавычек.
Синтаксис и пример
Replace([ProductName]; "-"; " ")
Результат: каждое вхождение «-» заменено пробелом; поиска и замены по таблице это не меняет.

IIf условное значение

Мгновенное «если… то… иначе» прямо в выражении: условие; значение если Да; значение если Нет.
Синтаксис и пример
IIf([UnitPrice] > 10000; "Дорого"; "Недорого")
Результат: для цены 25000 выражение вернёт Дорого; для 1200 — Недорого.

Цепочка очистки денежного значения — текст → Val → CCur → денежное поле

Каждый шаг превращает «грязное» значение из выгрузки в тип, с которым Access умеет работать: сначала число, затем деньги.

Работа с текстом

& · Left · Right · Mid · Len · UCase / LCase · Trim · InStr · Replace — как меняется строка
Текстовые значения всегда в двойных кавычках: "Стол"

& объединение строк

Склеивает текст, числа и поля в одну строку; пробелы между частями нужно ставить самому.
Синтаксис и пример
[Brand] & " " & [ProductName]
Результат: "Logitech Мышь MX". Если хоть одно поле Null — вся строка станет Null: оберните поля в Nz (блок 6).

Left первые символы

Отрезает заданное количество символов слева — коды, префиксы артикулов.
Синтаксис и пример
Left([ProductName]; 5)
Результат: "Компь" из строки "Компьютерный стол".

Right последние символы

Отрезает символы справа — год из кода документа, расширение файла, суффикс.
Синтаксис и пример
Right([КодДокумента]; 4)
Результат: "2024" — год выделяется из кода без разбора строки вручную.

Mid подстрока с позиции

Берёт символы начиная с указанной позиции (нумерация с 1) и в заданном количестве.
Синтаксис и пример
Mid([ProductName]; 2; 3)
Результат: "тол" из строки "Столик" — позиции 2, 3, 4.

Len длина строки

Считает символы в строке — контроль заполнения полей перед загрузкой в поле фиксированного размера.
Синтаксис и пример
Len([ProductName])
Результат: "Стол" → 4; пробелы внутри тоже считаются.

UCase · LCase регистр

UCase поднимает строку в верхний регистр, LCase опускает в нижний — унификация справочников.
Синтаксис и пример

Результат: "Авто" → "АВТО" или "авто" — единый регистр для GROUP BY.

Trim пробелы по краям

Срезает начальные и конечные пробелы; внутренние пробелы не трогает.
Синтаксис и пример
Trim([ProductName])
Результат: "␣␣Стол␣␣" → "Стол" — чистые значения для сравнений и группировок.

InStr позиция подстроки

Возвращает номер позиции, с которой начинается подстрока; 0 — если не найдена.
Синтаксис и пример

Результат: "Стол телефонный" → 6 — подстрока начинается с 6-й позиции.

Replace замена в строке

Меняет все вхождения подстроки — нормализация разделителей и дефисов перед загрузкой данных.
Синтаксис и пример
Replace([ProductName]; "-"; " ")
Результат: "Стол-компьютерный" → "Стол компьютерный"; схема преобразования типов — в блоке 6.

Date · Now сегодня; сегодня и время

Выделяют из даты год, номер месяца и день — для группировки по периодам.
Синтаксис и пример ([OrderDate] = 15.01.2024)

Результат: из одной даты получаются три числа — строительные блоки для отчётов по периодам.

DateAdd прибавить интервал

Сдвигает дату на заданное число интервалов: "yyyy" — годы, "m" — месяцы, "d" — дни.
Синтаксис и пример

Результат: 15.01.2024 → 15.02.2024 — срок оплаты, гарантия, следующая поставка.

DateDiff разница между датами

Считает, сколько интервалов помещается между двумя датами: дней, месяцев, лет.
Синтаксис и пример

Результат: 47 — возраст заказа в днях; с "m" и "yyyy" — возраст в месяцах и годах.

Превращает дату в строку нужного вида — для выгрузок и подписей в отчётах.
Синтаксис и пример
Format([OrderDate]; "dd.mm.yyyy")
Результат: строка "15.01.2024"; шаблон "mm.yyyy" даёт метку периода "01.2024".

Частые ошибки — и как их исправить

каждая карточка: ошибка → причина → исправление
Большинство ошибок Access — в именах полей, кавычках и разделителях

Окно «Введите значение параметра»

При запуске запроса Access неожиданно просит ввести значение — хотя вы ничего не спрашивали.
причина
Опечатка в имени поля: UnitPrise вместо UnitPrice — Access считает это неизвестным параметром.
Исправление: сверить имена полей с Конструктором таблицы; поле есть, но не в этом запросе? Добавьте таблицу.

«Ошибка синтаксиса (пропущен оператор)»

Запрос не запускается, Access ругается на пропущенный оператор или разделитель.
причина
Неправильный разделитель аргументов или кавычки: IIf([Цена] > 10000, "Да", "Нет") — запятые в русской локали.
Исправление: в выражениях — точка с запятой; текст — в двойных кавычках: IIf([Цена] > 10000; "Да"; "Нет")
ошибкаок
; → , в выражении✗
'Одинарные' кавычки✗
IIf(a; "Да"; "Нет")✓

Null и пустая строка «»

Поле «пустое» по-разному: Null — значение отсутствует вообще, "" — введена пустая строка.
причина
Условие = "" не находит поля с Null, а IS NULL не находит пустые строки — часть записей «пропадает».
Исправление: искать оба случая сразу: WHERE Поле IS NULL OR Поле = "" — или чистить данные Trim'ом.
значение поляIS NULL= ""
Null✓✗
"" (пустая строка)✗✓

Неправильный тип PK / FK

Связь не создаётся или JOIN не находит пар: типы связанных полей различаются.
причина
Ключ AUTOINCREMENT связан с текстом или числом не того размера — сравнение значений ломается.
Исправление: с полем AUTOINCREMENT связывать поле типа LONG — и никак иначе.

Даты без решёток #

Дата в условии записана как текст — сравнение не срабатывает или выдаёт мусор.
причина
WHERE OrderDate = "01.03.2024" — кавычки превращают дату в строку.
Исправление: литералы дат между решётками: WHERE OrderDate = #2024-03-01#
запись условияитог
= "01.03.2024"✗ текст
= #2024-03-01#✓ дата

UPDATE / DELETE без проверки

Команда выполнена «не на тех» строках — а отменить изменение в Access нельзя.
причина
Слишком широкое WHERE — или его забыли совсем: DELETE FROM Products; очистит всю таблицу.
Исправление: сначала SELECT с тем же WHERE, убедиться в списке строк — и только потом менять/удалять.
