# Гайд по тестированию учебника

Инструкция по ручной и автоматической проверке HTML-учебника «Microsoft Access 2007–2016 для аналитика». Применяется после любых правок страниц, скриптов и стилей, а также перед сборкой ZIP-архива.

---

## 1. Как открывать учебник

- **Локально, многостраничная версия:** двойной щелчок по index.html в корне репозитория. Все страницы модулей лежат в modules/, навигация идёт по относительным ссылкам; сервер не требуется.
- **Локально, самодостаточная версия:** standalone.html — сборка, в которой все модули, стили и скрипты вшиты в один файл; открывается офлайн двойным щелчком, роутер работает по хэшу вида #/m07/s-sql.
- **GitHub Pages:** та же структура по публичному URL репозитория; проверяйте, что относительные пути не ломаются, а ссылки на docs и datasets открываются из страниц модулей.

## 2. Чек-лист из 18 пунктов

Проверка проводится в двух браузерах (Chrome и Firefox) в трёх режимах открытия: index.html, standalone.html, GitHub Pages. Пункт считается пройденным, когда ожидаемый результат воспроизводится во всех шести комбинациях.

### 1) index.html открывается
Проверка: двойной щелчок по index.html в файловом менеджере. Ожидается: титульная страница курса, сайдбар с 15 модулями и разделом «Датасеты», без ошибок вёрстки.

### 2) standalone.html открывается
Проверка: открыть standalone.html офлайн. Ожидается: тот же контент в одном файле, переходы между модулями по хэш-роуту, поиск работает.

### 3) Относительные ссылки работают из корня и из modules/
Проверка: пройтись по ссылкам docs и datasets в подвале сайдбара с титульной страницы и с любой страницы модуля. Ожидается: обе ссылки открываются с обеих страниц (префикс пути подставляется автоматически).

### 4) Боковое меню и «Назад/Далее»
Проверка: клики по пунктам сайдбара, затем кнопки «Назад» и «Далее» на каждой странице. Ожидается: порядок модулей m01 и далее по возрастанию, активный пункт подсвечен, на m01 «Назад» ведёт на титульную, на m15 «Далее» скрыта.

### 5) Оглавление модуля и scrollspy
Проверка: открыть любой модуль, посмотреть панель оглавления, прокрутить страницу. Ожидается: 17 секций, активный пункт подсвечивается при прокрутке, клик плавно ведёт к секции.

### 6) Поиск
Проверка: нажать `/` или `Ctrl+K`, ввести «каскад», затем один символ, затем `Esc`. Ожидается: диалог открывается от клавиши и от кнопки; при менее чем 2 символах результатов нет; по Enter или клику происходит переход к найденному модулю; `Esc` закрывает диалог.

### 7) Тёмная и светлая тема
Проверка: переключить тему на титульной странице и в модуле, перезагрузить страницу. Ожидается: тема применяется к оболочке и содержимому, выбор сохранён в localStorage после перезагрузки; при первом визите берётся системная настройка.

### 8) Индикатор прогресса и отметка «модуль пройден»
Проверка: открыть модуль, нажать «Модуль пройден», перезагрузить страницу. Ожидается: прогресс-бар в шапке и сайдбаре обновился, отметка сохранилась после перезагрузки, сброс в настройках очищает прогресс.

### 9) Чек-листы сохраняют состояние
Проверка: отметить 3 пункта чек-листа самостоятельной работы любого модуля, перезагрузить. Ожидается: галочки на месте (ключи вида m07:3 в localStorage), снятие галочки тоже сохраняется.

### 10) Решения раскрываются и раскрываются при печати
Проверка: кликнуть «Показать эталонное решение» на экране, затем отправить страницу в предпросмотр печати. Ожидается: на экране блок открывается и закрывается; при печати закрытые блоки раскрываются автоматически (обработчик beforeprint).

### 11) Тесты модулей
Проверка: пройти тест модуля с ошибками, затем пересдать без ошибок. Ожидается: после проверки видны пояснения к каждому вопросу, результат ниже 80 % помечен как незачёт, после пересдачи сохраняется лучший результат, кнопка ретейка доступна всегда.

### 12) Ссылки Kaggle открываются в новой вкладке
Проверка: открыть раздел «Датасеты», кликнуть ссылки Olist, Superstore, Online Retail. Ожидается: каждая открывается в новой вкладке браузера и ведёт на реальную страницу набора; внутри модулей внешних ссылок нет — только текстовая отсылка к разделу «Датасеты».

### 13) Печать и PDF
Проверка: предпросмотр печати модуля и всего курса. Ожидается: оболочка (сайдбар, топбар) скрыта, титульная страница с оглавлением курса, таблицы и блоки кода не разрываются между страницами, колонтитулы браузера дают номера страниц.

### 14) Экспорт текущего модуля в Markdown
Проверка: панель экспорта, действие «Экспорт текущего модуля в Markdown», открыть файл. Ожидается: заголовки H1–H3, таблицы в синтаксисе Markdown, код в ограждённых блоках, чек-боксы и тесты представлены читаемо.

### 15) Экспорт всего курса в Markdown и TXT
Проверка: экспортировать весь курс в обоих форматах, открыть файлы. Ожидается: все 15 модулей по порядку с титульной информацией; экспорт работает офлайн из встроенного кэша.

### 16) Копирование раздела и всего курса
Проверка: «Скопировать текущий раздел», вставить в текстовый редактор. Ожидается: буфер содержит текст раздела с разметкой; копирование всего курса повторяет содержимое экспорта в Markdown.

### 17) Мобильная вёрстка
Проверка: сузить окно до 720px и ниже, затем до 420px (или режим устройства в DevTools). Ожидается: сайдбар спрятан за кнопкой-бургером и выдвигается, таблицы прокручиваются горизонтально внутри обёртки, текст не выходит за границы экрана.

### 18) Консоль браузера без ошибок
Проверка: открыть DevTools (F12), вкладка Console, обойти титульную страницу, 3–4 модуля, поиск, тест, экспорт. Ожидается: нет красных ошибок и предупреждений о битых ресурсах (картинки, CSS, JS).

## 3. Проверка ZIP-архива

Сборка выполняется скриптами build-zip.sh (Linux и macOS) или build-zip.ps1 (Windows) из корня репозитория.

- [ ] В архиве нет служебного мусора: .git, Thumbs.db, .DS_Store, файлы *.tmp, *.log отсутствуют.
- [ ] Размер архива адекватен содержимому (ориентир — до 3 МБ: HTML, CSS, JS, SVG, документы датасетов).
- [ ] Состав соответствует репозиторию: index.html, standalone.html, modules/ (15 файлов), css/ (3), js/ (6), assets/, diagrams/, datasets/, sql/, vba/, docs/.
- [ ] Распаковка в чистую папку завершается без ошибок путей и кодировки.
- [ ] index.html из распакованной папки открывается двойным щелчком: сайдбар, поиск и экспорт работают, в консоли нет ошибок битых путей.

```bash
class P(HTMLParser): pass
for f in glob.glob('modules/*.html') + ['index.html']:
    P().feed(open(f, encoding='utf-8').read())
    print('parsed OK:', f)
PY

# 3. Пересборка standalone-версии по скрипту сборки (инъекция кэша и стилей)

# 4. Запрещённые фразы: страницы курса и документация без них;

```

Дополнительные точечные проверки по стандарту модулей: data-module уникален, 17 секций с якорями s-goals и s-summary, quiz-JSON парсится, в pre и code экранированы амперсанд и угловые скобки, CJK-иероглифов нет.

Проверка после пересборки standalone:

- [ ] Размер файла вырос не более чем на размер добавленного контента (кэш вшит один раз).
- [ ] Все 15 модулей доступны через хэш-роут #/m01 и далее.
- [ ] Экспорт всего курса из standalone отдаёт те же файлы, что и многостраничная версия.
- [ ] Поиск из standalone находит фразу из последнего модуля (кэш полный, а не частичный).

## 5. Как сообщать об ошибках и вносить правки

Сообщения об ошибках оформляются в ISSUE по шаблону:

```markdown
**Страница:** modules/08-analytics.html
**Браузер и ОС:** Chrome 120, Windows 11
**Шаги воспроизведения:** 1. открыть модуль 08; 2. запустить тест; 3. ответить на вопрос 4
**Ожидаемо:** показывается пояснение к ответу
**Реально:** пояснение не появляется, в консоли ошибка
```

Правки вносятся через pull request: одна правка — одна тема; к PR прикладывается вывод регрессии из раздела 4 и номера пунктов чек-листа из раздела 2, которые проверены вручную. Изменения эталонных чисел датасета согласуются с `../../module-spec.md` (раздел 2.3) и пересчитываются скриптом, а не вручную.
