# Руководство преподавателя

Методические материалы к HTML-учебнику «Microsoft Access 2007–2016 для аналитика»: три формата проведения, темп, организация проверки, типовые трудности студентов, правила расширения курса и методические запреты. Общая трудоёмкость курса — 80 академических часов; ядро — 15 страниц модулей в каталоге modules/.

---

## 1. Учебник в трёх форматах

### 1.1. Очный курс

- Занятие строится по модели модуля: теория и демонстрация (секции theory и demo) выводятся на экран, студенты повторяют шаги на своих машинах.
- Секция case разбирается устно: слушатели сначала предлагают решение, затем сравнивают с текстом модуля.
- Секции sql и designer студенты выполняют самостоятельно, преподаватель ходит по аудитории и смотрит на сетку QBE и SQL-режим.
- Домашнее чтение — следующий модуль целиком; на следующем занятии первые 15 минут: разбор ошибок из «Типичных ошибок» прочитанного модуля и выборочная проверка 2–3 пунктов чек-листов.

### 1.2. Дистанционный формат

- Студенты проходят модули самостоятельно; преподаватель задаёт недельные цели по маршруту из [student-checklist.md](student-checklist.md).
- Ответы на «Контрольные вопросы» модуля собираются письменно; тесты модулей выступают фильтром готовности — к следующему модулю пускают после 80 %.
- Раз в неделю — онлайн-разбор одной самостоятельной работы: экран студента, преподаватель направляет по критериям секции criteria.
- Итоговая защита проводится по видеосвязи с демонстрацией экрана по демо-маршруту из модуля 15.

### 1.3. Смешанный формат (основной)

- Между занятиями студенты читают модуль и выполняют самостоятельную работу с чек-листом.
- На занятии: разбор типовых ошибок, эталонное решение из details.solution, новое задание модуля под присмотром.
- Такой режим держит аудиторную нагрузку в пределах двух пар в неделю при общей трудоёмкости 80 академических часов (остальное — домашняя работа, тесты и проект).

Домашние чтения и разборы: на каждую неделю назначается один модуль для чтения дома и один для разбора на занятии; разбор строится вокруг секций mistakes и tips — именно там собраны реальные ловушки. Проверка чтения — тест модуля (порог 80 %) и три пункта чек-листа по выбору преподавателя.

### 2.1. Где можно ускоряться

Слушателям с сильным SQL модули 06–08 разрешается проходить по секциям demo и result, пропуская построчный разбор SQL: диалект Access отличается от T-SQL и MySQL в деталях (решётки дат, звёздочка в Like, IIF вместо CASE, TOP вместо LIMIT), но не по сути. Самостоятельные работы и задания S01–S04, I01, I02, S05 при этом обязательны: диалект проверяется руками.

### 2.2. Где ускоряться нельзя

- **m03 (связи).** Это фундамент всей базы: без правильных связей и каскадов проект на m15 не собирается, а ошибки целостности всплывают на импорте.
- **m08 (action-запросы).** Необратимые операции: студент, пропустивший бэкап и протокол изменений, теряет данные при выполнении проекта.
- **m14 (разделение базы).** BE/FE и переподключение таблиц — самый частый источник «мёртвых» проектов при сдаче: файлы переименованы, ссылки сломаны, диспетчер связанных таблиц не запущен.

## 3. Как проверять

### 3.1. Тесты модулей

- Порог 80 % правильных ответов; пересдача разрешена после повторного прохождения секций theory и demo.
- Результат сохраняется в браузере студента; остается лучший результат.
- На очных занятиях устраивается общий разбор вопросов, на которые ошиблось большинство: формулировки теста дают быстрый срез понимания.

### 3.2. Самостоятельные работы

- Критерии из секции criteria каждого модуля: совпадение результата с эталоном по составу строк; отсутствие «мусорных» объектов; имена по соглашению qry_, frm_, sfrm_, rpt_, mcr_; требуемая настройка действительно включена.
- Чек-листы mNN-self — самоконтроль студента; преподаватель выборочно сверяет 2–3 пункта, а не весь список.
- Что смотреть в файле студента в первую очередь: количество строк результата, наличие лишних таблиц вида CopyOf и Query1, включённость условия на значение и каскада там, где задание их требовало.

### 3.3. Задания E01–V02

- В каждой карточке полный эталон в скрытом блоке details.solution: SQL целиком или пошаговый маршрут.
- Быстрая проверка ведётся по «Ожидаемому результату» карточки: например, qry_Заказы2018 — ровно 5 заказов 2018 года, O-10010 со статусом processing исключён.
- Уровни заданий: E — начальные (E01–E05), I — средние (I01–I05), S — SQL (S01–S05), F — формы и отчёты (F01–F03), V — макросы и VBA (V01–V02); суммарно 20 карточек, распределение — в таблице раздела 6 [course-outline.md](course-outline.md).

### 3.4. Итоговый проект

- Чек-лист m15-final из 20 пунктов внутри модуля 15: студент отмечает сам, преподаватель проверяет спорные.
- Защита — 7–10 минут по демо-маршруту: открытие FE, панель frm_Панель, frm_Заказы с подчинённой, отчёты, экспорт кнопкой, макрос, объяснение разделения BE/FE.
- Оценка — 100 баллов: данные 20, запросы 25, интерфейс 20, отчёты 15, автоматизация 10, эксплуатация 10; порог 70.
- Типовые вопросы защиты (8 штук с краткими ответами) — в секции control модуля 15; задавайте минимум три из них каждому студенту.

## 4. Типовые трудности студентов

**Ведущие нули.** Классический сбой курса: ZipCodePrefix 01310 после импорта превращается в 1310, потому что мастер определил поле как Числовой. Студенты недоумевают, куда пропал ноль. Показывайте проверку типов сразу после мастера импорта (модуль 04) и правило: текстовые ключи из внешних систем — только Короткий текст. Если данные уже испорчены, лечение одно: удалить таблицу и повторить импорт; правка вручную ведёт к рассинхронизации ключей.

**Даты в решётках.** Привычка из T-SQL заставляет писать кавычки вокруг дат, а Access требует решётки: #2018-01-01#. Типовый симптом — сообщение «несоответствие типов данных в выражении условия отбора». Отработайте на задании S01 в модуле 07 и держите под рукой таблицу диалекта из теории модуля: решётки, звёздочка в Like, IIF вместо CASE, TOP вместо LIMIT, квадратные скобки вокруг имён с пробелами.

**Каскады.** Студенты либо боятся включать каскадное удаление, либо включают его везде и теряют позиции заказов. Разберите в модуле 03 контрольный эксперимент: попытка удалить категорию automotivo с товарами отклоняется целостностью, а удаление заказа O-10006 с включённым каскадом уносит и его строки из OrderDetails. Правило курса: каскад включается только там, где дочерние записи не существуют без родителя.

**Параметры-формы.** Ссылка Forms!frm_Панель!НачальнаяДата в условии запроса ломается трижды: опечатка в имени формы или поля, отсутствие квадратных скобок, неявный тип параметра. Учите явно объявлять PARAMETERS с типом DateTime (модуль 08) и сначала проверять ссылку в немедленном окне Immediate, прежде чем встраивать её в условие запроса.

**Recordset.** Прикладной VBA пугает конструкцией Set rs = CurrentDb.OpenRecordset с последующим Do While Not rs.EOF. Методика модуля 12: не писать, а читать готовую процедуру, прогнать её пошагово (F8), напечатать значения через Debug.Print в Immediate. Студент, который может предсказать вывод процедуры до запуска, готов к заданию V02.

## 5. Как расширять курс

### 5.1. Добавить модуль

1. Скопируйте соседнюю страницу из каталога modules/ по уровню и блоку (например, для нового модуля блока B — копия 08-analytics.html).
2. Сохраните скелет: 17 секций с якорями s-goals и s-summary, маркеры CACHE-START и CACHE-END, шесть подключаемых скриптов js/.
3. Измените body data-module на уникальный идентификатор (например, m16), title, чипы блока и часов, ключ чек-листа data-checklist.
4. Зарегистрируйте страницу в манифесте AC.MANIFEST в js/app.js — иначе сайдбар, поиск, прогресс и экспорт её не увидят.
5. Соберите standalone и прогоните проверки из [testing-guide.md](testing-guide.md).

### 5.2. Добавить задание

1. Оформите карточку task-card по разделу 6.5 контент-стандарта `../../module-spec.md`: все 11 обязательных элементов от чипов уровня и времени до «Дополнительного усложнения».
2. Эталонное решение пишется целиком в details.solution: SQL без сокращений или пошаговый маршрут по ленте.
3. Идентификатор data-task должен быть уникальным; карточка размещается в секции homework после чек-листа самостоятельной работы.
4. Новые числа пересчитываются по мини-датасету скриптом и сверяются с контрольными значениями из [course-outline.md](course-outline.md), раздел 10.1.

### 5.3. Обновить данные

1. Датасет живёт в трёх местах: datasets/data-dictionary.md (поля), datasets/import-instructions.md (пути получения), раздел 2.3 `../../module-spec.md` (мини-датасет). При изменении полей обновляются все три.
2. Контрольные числа (3 025,50 по категориям и заказам) встречаются в модулях 08, 12 и 15; после правки данных пересчитайте и их.
3. Правки эталонов вносятся только через программный пересчёт по строкам мини-датасета; ручная арифметика в голове — источник расхождений между модулями.

## 6. Методические запреты

- **Не давать VBA «с нуля».** Не начинайте с типов данных, операторов и циклов: курс обещает прикладной уровень. Первый контакт с кодом — чтение работающей процедуры сквозного проекта. Студент, которого раньше «просадили» синтаксисом, теряет мотивацию ровно на модуле 12.
- **Не проверять «какая кнопка третья слева».** Вопросы про расположение элементов интерфейса запрещены стандартом курса: ленты разных версий различаются. Проверяйте понимание и выбор действия в ситуации: какой тип данных выбрать, какое соединение дать, что произойдёт при удалении родителя.
- **Не пропускать очистку данных.** Импорт без staging и дедупликации — ловушка: ошибки проявятся на связях и отчётах за несколько модулей до причины. Если время поджимает, сокращайте демонстрации, но не этапы очистки модуля 05: без него эталонные числа проекта не сходятся.
- **Не ставить задания вне датасета ShopData.** Придуманные задачи на чужих данных ломают сквозную линию и эталонные решения; расширения допускаются только по правилу раздела 12 контент-стандарта с явным объявлением в секции data.
- **Не принимать объекты без имён по соглашению.** Запрос с именем Query1 в сдаче проекта считается ошибкой эксплуатации, даже если результат верен: переименование — часть навыка.
