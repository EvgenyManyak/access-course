# 📗 Microsoft Access 2007–2016 — интерактивный учебник для аналитика

Статический HTML-учебник без серверной части: работает локально при открытии файла, публикуется через GitHub Pages и скачивается одним архивом. Курс ведёт пользователя Excel и аналитика со знанием SQL от первой таблицы до разделённой базы front-end/back-end с формами, отчётами, макросами и прикладным VBA.

- **15 модулей**, каждый — 17 обязательных секций: цели, теория, пошаговая демонстрация, кейс аналитика, SQL с разбором по строкам, вариант через конструктор, типичные ошибки, советы, самостоятельная работа, тест 6–8 вопросов, контрольные вопросы, критерии, скрытое эталонное решение, резюме.
- **20 практических заданий** (5 начальных, 5 средних, 5 SQL, 3 формы/отчёты, 2 макросы/VBA) на одном сквозном датасете **ShopData**.
- **Интерактив:** сайдбар с оглавлением и прогрессом, поиск по всему курсу, тесты с пояснениями, чек-листы, тёмная тема, клавиатурная навигация, панель экспорта (PDF/HTML/Markdown/TXT/буфер обмена).
- **Офлайн-стек:** чистые HTML + CSS + JavaScript, без сборки, без зависимостей, без серверного кода.

## 📖 Описание

Учебник закрывает типовой разрыв: аналитик свободно работает в Excel (сводные, ВПР, формулы) и знает SQL (SELECT, JOIN, GROUP BY), но никогда не собирал в Access законченное решение. Курс построен на четырёх принципах:

1. **От привычного к новому** — каждый объект Access объясняется через знакомый образ: таблица — «умный лист Excel», запрос — «сохранённый SQL + сводная», форма — «защищённый экран ввода», отчёт — «печатная форма».
2. **Один датасет** — все 20 заданий, тесты и итоговый проект выполняются на сквозном датасете ShopData (интернет-магазин, основа — Kaggle Olist Brazilian E-commerce): полный путь данных CSV/XLSX → импорт → очистка → нормализация → связи → запросы → формы → отчёты → экспорт.
3. **Прикладной VBA** — язык не преподаётся «с нуля»: студент читает готовый код (`vba/*.bas`), запускает процедуры, обрабатывает события и автоматизирует формы, запросы, импорт и экспорт.
4. **Проверяемость** — каждый модуль завершается тестом с порогом 80%, критериями проверки и эталонными решениями в раскрывающихся блоках.

Общая трудоёмкость — **80 академических часов** (34 теория + 46 практика), рекомендуемый темп — 10–12 недель. Подробная программа: [`docs/course-outline.md`](docs/course-outline.md).

## 🎯 Целевая аудитория

- Пользователи Excel и аналитики данных со знанием SQL на уровне SELECT … JOIN … GROUP BY, **без практического опыта Access**.
- Бизнес-аналитики, финансовые аналитики, специалисты отчётности, получающие данные выгрузками CSV/XLSX.
- **Не требуется:** опыт программирования, знание VBA, опыт проектирования БД — всё даётся с прикладной стороны. VBA — только на прикладном среднем уровне.

## 🖥 Инструкция по локальному запуску

**Вариант 1 — просто открыть файл (основной):**

1. Скачайте проект (ZIP или `git clone`).
2. Откройте `index.html` двойным щелчком в любом современном браузере — Chrome, Edge, Firefox или Safari.
3. Учебник работает полностью офлайн: сайдбар, поиск, тесты, прогресс и экспорт не требуют сервера.

**Вариант 2 — всё в одном файле:**

- Откройте `standalone.html` — весь курс (15 модулей + главная + датасеты) в одном файле; удобно переносить на планшет или пересылать.

**Вариант 3 — локальный веб-сервер (необязательно, для поведения «как на сайте»):**

```bash
cd access-course
python3 -m http.server 8000
# откройте http://localhost:8000
```

Это не серверная часть учебника (её нет), а просто способ раздачи статических файлов. Прогресс курса хранится в localStorage браузера и привязан к адресу страницы: при смене протокола (file:// ↔ http) или папки браузер видит «новое» хранилище.

## 🌐 Инструкция по публикации через GitHub Pages

1. **Создайте репозиторий.** На github.com нажмите **New repository**, задайте имя (например, `access-course`), Public, без README (он уже есть в проекте).
2. **Загрузите проект.** Любой способ:
   - веб-интерфейс: **Add file → Upload files** и перетащите содержимое папки (не саму папку, а её содержимое — `index.html` должен оказаться в корне репозитория);
   - или из консоли:
     ```bash
     git init
     git add .
     git commit -m "Initial commit: Access course"
     git branch -M main
     git remote add origin https://github.com/<ваш-логин>/access-course.git
     git push -u origin main
     ```
3. **Ветка.** Используйте `main` — GitHub Pages рекомендует её как источник публикации.
4. **Папка.** Выберите **Deploy from a branch → main → / (root)** — сайт публикуется из корня репозитория, вложенная папка не нужна.
5. **Включите GitHub Pages.** Settings → Pages → Source: «Deploy from a branch», Branch: `main`, folder: `/ (root)` → Save.
6. **Публичная ссылка.** Через 1–2 минуты сайт появится по адресу `https://<ваш-логин>.github.io/access-course/`. Ссылка показывается в Settings → Pages.
7. **Обновление проекта.** `git add . && git commit -m "Обновление" && git push` — Pages переразворачивается автоматически; в отдельные папки репозитория добавить `.nojekyll` не требуется (в проекте нет файлов с подчёркиванием в корне, но при желании создайте пустой `.nojekyll` — это безвредно).
8. **Проверка относительных ссылок.** Все ссылки в проекте относительные (`css/…`, `js/…`, `modules/…`, `../…`), поэтому при публикации в подкаталог (`/access-course/`) ничего править не нужно. Проверьте в браузере: DevTools → Network — не должно быть 404; кликните «Главное меню → любой модуль → Назад».
9. **Проверка локального и опубликованного вариантов.** Пройдите чек-лист [`docs/testing-guide.md`](docs/testing-guide.md) в обоих режимах: откройте `index.html` с диска и сайт по ссылке — поведение (навигация, поиск, тесты, экспорт) должно совпадать; экспорт «весь курс» работает в обоих случаях, потому что кэш содержимого зашит в `js/export.js` на этапе сборки.

## 📦 Инструкция по созданию ZIP-архива

Архив собирается скриптом из корня проекта. Имя результата: **`access-course-project.zip`**.

**Windows (PowerShell):**

```powershell
cd C:\path\to\access-course
powershell -ExecutionPolicy Bypass -File .\build-zip.ps1
```

**Linux / macOS (bash):**

```bash
cd /path/to/access-course
chmod +x build-zip.sh
./build-zip.sh
# если нет zip: sudo apt-get install zip  |  brew install zip
```

Скрипты исключают `.git/`, временные и системные файлы (`Thumbs.db`, `.DS_Store`, `*.tmp`, `*.temp`, `*.log`, `node_modules/`, `.vscode/`, `*~`), выводят список файлов в архиве, размер архива и проверяют результат. Команда проверки архива после сборки:

```bash
unzip -l access-course-project.zip | tail -5     # список и итог (Linux/macOS)
tar -tf access-course-project.zip | wc -l        # число файлов
unzip -t access-course-project.zip               # тест целостности
```

В PowerShell проверка: `Expand-Archive access-course-project.zip -DestinationPath ..\check -Force`.

## 📤 Инструкция по открытию ZIP-архива

1. Скачайте `access-course-project.zip` и распакуйте **в новую пустую папку** (правый клик → «Извлечь всё…» в Windows; `unzip access-course-project.zip` в Linux/macOS; двойной клик в macOS).
2. Внутри появится папка `access-course/` со всей структурой проекта.
3. Откройте `access-course/index.html` двойным щелчком — проверьте, что загрузилась главная страница с боковым меню.
4. Не переименовывайте папки и не перемещайте файлы поодиночке: все ссылки относительные, структура должна сохраниться.
5. Если антивирус предупреждает о макросах — в архиве их нет: это статические HTML/CSS/JS; макросы Access создаются студентом вручную в Access по модулям 11–12.

## 🖨 Инструкция по использованию экспорта в PDF

1. Откройте любой модуль и нажмите **⬇ Экспорт → Печать / сохранить в PDF** (или Ctrl+P).
2. В диалоге печати выберите «Сохранить как PDF» (Chrome/Edge) или «PDF → Сохранить как PDF» (Firefox/Safari).
3. Печатные стили автоматически: скрывают боковое меню и кнопки, добавляют титульную страницу с оглавлением курса, раскрывают скрытые решения, не разрывают таблицы и блоки кода, печатают заголовки и ссылки (адреса внешних ссылок — в скобках).
4. **Номера страниц** проставляются браузером: включите в диалоге печати параметр «Колонтитулы» / «Headers and footers» (Chrome: Дополнительные настройки). Кнопка «Колонтитулы» также добавит дату и адрес документа.
5. Формат A4 и поля заданы в `css/print.css` (`@page`); кириллица корректна, так как используются системные шрифты.
6. Печать всей книги: откройте `standalone.html` и напечатайте его — титульная страница, оглавление и все модули пойдут сплошным документом.

## 📝 Инструкция по экспорту в Markdown и TXT

Панель **⬇ Экспорт** содержит 8 действий. Для Markdown и TXT файлы создаются в браузере через Blob и атрибут `download` — скачиваются «Downloads» без сервера:

- **Экспорт текущего модуля в Markdown** — `.md` с заголовками, таблицами, кодом (в блоке ```sql/```vba), коллаутами и тестами с правильными ответами;
- **Экспорт всего курса в Markdown** — один `access-course-full.md`: главная + 15 модулей + датасеты;
- **Экспорт текущего модуля / всего курса в TXT** — простой текст для заметок и grep-поиска;
- **Скопировать текущий раздел / весь курс** — тот же Markdown в буфер обмена.

Оба экспорта «весь курс» работают офлайн: содержимое всех страниц зашито в `js/export.js` (константа `COURSE_CACHE`, заполняется скриптом сборки). Конвертация в DOCX: откройте `access-course-full.md` в Microsoft Word (или `pandoc access-course-full.md -o course.docx`); XLSX: скопируйте таблицу из экспортированного HTML или откройте HTML-файл в Excel.

## ➕ Инструкция по добавлению новых модулей

1. Скопируйте ближайший по теме файл из `modules/`, например `02-tables.html` → `16-data-macros.html`.
2. Измените `<title>`, `<h1>` (включая `<span class="module-title__kicker">Модуль 16</span>`), чипы блока и уровня.
3. Заполните 17 секций с теми же `id` (`s-goals` … `s-summary`) и заголовками H2 — единая структура нужна поиску, оглавлению и прогрессу.
4. Сохраните маркеры `<!--CACHE-START-->` и `<!--CACHE-END-->` вокруг `<article class="module">` — по ним сборка наполняет `standalone.html` и поиск.
5. Зарегистрируйте модуль в **манифесте** `js/app.js`: добавьте запись в `AC.MANIFEST` (`id: 'm16'`, `file: 'modules/16-data-macros.html'`, `num: '16'`, `title`, `desc`, группа). Порядок в манифесте = порядок навигации и прогресса.
6. Если нужен тест — добавьте секцию `.quiz` с JSON (см. пример в любом модуле), если чек-лист — `data-checklist="m16-self"` и ключи `m16:1…N`.
7. Пересоберите `standalone.html` (см. [тестинг-гайд](docs/testing-guide.md), раздел «Регрессия») и обновите список модулей в этом README и в `index.html`.

## ⚠ Ограничения проекта

1. **Прогресс не синхронизируется** — хранится в localStorage конкретного браузера на конкретном устройстве; перенос между браузерами и устройствами не выполняется (экспорт прогресса не предусмотрен).
2. **Служба поиска — клиентская**: поиск ищет по зашитому кэшу содержимого; при изменении модулей нужна пересборка (см. тестинг-гайд), иначе поиск находит старый текст.
3. **Экспорт HTML** — статический снимок раздела со встроенными стилями, без JS-интерактива (тесты и поиск в выгрузке не работают; решения печатаются раскрытыми).
4. **DOCX/XLSX не генерируются в браузере** — панель экспорта честно предлагает пути конвертации (Word/Pandoc/Excel), не имитируя генерацию.
5. **Номера страниц в PDF** ставит браузер (опция «Колонтитулы»), а не CSS — полный контроль постраничной вёрстки в браузере недоступен.
6. **VBA-код из `vba/*.bas` требует Access** — учебник проверяет знания, но запускать код нужно в Microsoft Access 2007+; в браузере VBA не исполняется.
7. **Проверено на современных браузерах** (Chrome/Edge ≥ 90, Firefox ≥ 90, Safari ≥ 14); в старых браузерах (IE11) интерфейс не гарантируется.
8. **Тесты хранят лучший результат локально** — пересдачи не ограничены, «античита» нет: это тренажёр, а не экзамен.
