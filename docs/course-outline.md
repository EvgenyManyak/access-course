# Программа курса «Microsoft Access 2007–2016 для аналитика»

Документ описывает курс как учебную программу: паспорт, результаты обучения, карту модулей HTML-учебника, модель модуля, систему оценивания, учёт версий Access и сквозной проект ShopData. Содержательная основа — программа курса в `../../scripts/access_course/c1.js` и контент-стандарт модулей `../../module-spec.md`.

---

## 1. Название и назначение

**«Microsoft Access для аналитика: от Excel и SQL к реляционной базе данных и прикладному VBA»** — практический курс по Microsoft Access 2007–2016, реализованный в виде интерактивного HTML-учебника. Курс закрывает типовой разрыв в навыках: аналитик свободно работает в Excel и знает SQL, но никогда не собирал в Access законченное решение — от импорта сырых файлов до форм, отчётов, макросов и разделённой базы.

VBA подключается на прикладном среднем уровне: сначала студент читает готовый работающий код сквозного проекта, запускает и модифицирует его. Язык программирования «с нуля» (типы данных, операторы, синтаксис) курс не преподаёт.

## 2. Аудитория и входные требования

Целевой слушатель — аналитик данных, ежедневно использующий Excel (сводные таблицы, ВПР/VLOOKUP, формулы) и знакомый с SQL на уровне SELECT, JOIN, GROUP BY. Курс также подходит бизнес-аналитикам, финансовым аналитикам и специалистам reporting, которые получают данные в виде CSV и XLSX-выгрузок и хотят перенести рабочие процессы из «плоского» Excel в реляционную модель.

| Категория | Требования |
|---|---|
| **Обязательно** | Уверенный Excel: структура листов, ссылки, сводные таблицы, базовые функции. Понимание SQL уровня SELECT, FROM, WHERE, JOIN, GROUP BY. Навыки работы с файлами CSV и XLSX |
| **Желательно** | Представление о принципах реляционных БД (таблица, строка, столбец). Опыт визуализации отчётов. Базовое чтение английского для имён полей и сообщений Access |
| **Не требуется** | Опыт программирования, знание VBA, опыт проектирования БД, знание Access — всё это курс даёт с прикладной стороны |

## 3. Длительность и форматы

Общая трудоёмкость курса — **80 академических часов** (34 часа теории и демонстраций, 46 часов практики). Рекомендуемый темп — 10–12 недель по 6–8 академических часов в неделю. Форматы:

- **Очный курс** с преподавателем: занятия по расписанию, практика в аудитории, защита проекта на последнем занятии.
- **Дистанционный самостоятельный проход**: студент идёт по HTML-учебнику в своём темпе, проверяет себя тестами (порог 80 %) и чек-листами модулей.
- **Смешанный формат** с еженедельными консультациями: домашние чтения модулей между занятиями, разбор типовых ошибок на встречах.

Ядро курса в HTML-учебнике — 15 страниц модулей суммарной трудоёмкостью 55 академических часов (по чипам в шапках страниц). Остальные 25 часов (5,5 Т + 19,5 П) — резерв на прохождение тестов, сверку с чек-листами, повторение теории, подготовку и защиту итогового проекта. В сумме получается паспортные 34 Т + 46 П = 80 часов.

## 5. Принципы курса

- **От привычного к новому.** Каждый объект Access объясняется через знакомый образ: таблица — «умный лист Excel», запрос — «сохранённый SQL плюс сводная таблица», форма — «защищённый интерфейс ввода», отчёт — «готовая печатная форма». Опора на опыт снижает нагрузку и ускоряет переход от мышления ячейками к мышлению записями и связями.
- **Один датасет.** Все 20 заданий, все самостоятельные работы и итоговый проект выполняются на сквозном датасете розничной интернет-торговли ShopData (основа — Kaggle Olist Brazilian E-commerce). Студент проживает полный цикл данных: сырые файлы, импорт, очистка, связи, запросы, интерфейс, отчёты, автоматизация, эксплуатация. Мини-датасет для примеров зафиксирован в `../../module-spec.md` (раздел 2.3).
- **Прикладной VBA.** Модуль 12 начинается не с переменных и циклов, а с чтения готовой процедуры из сквозного проекта: студент разбирает код построчно, прогнозирует поведение, запускает и только затем модифицирует. Это соответствует реальной работе, где чаще достаётся чужой код, чем возможность писать с нуля.
- **Проверяемость.** Каждая учебная единица завершается контрольными вопросами, тестом с эталоном и критериями проверки. Эталонные решения вынесены в скрытые блоки `details.solution`: студент сначала выполняет работу сам, потом сверяется.

## 8. Система оценивания

Итоговая оценка складывается из четырёх компонентов:

| Компонент | Вес | Как проверяется |
|---|---:|---|
| Самостоятельные работы модулей (чек-листы mNN-self) | 30 % | Чек-листы в каждом модуле; преподаватель выборочно сверяет результаты с эталоном |
| Практические задания E01–V02 | 30 % | 20 карточек с полными эталонными решениями в details.solution |
| Тесты модулей | 20 % | JSON-тесты 6–8 вопросов; зачёт при 80 % правильных ответов; пересдача разрешена после повторного чтения теории и демонстрации |
| Итоговый проект | 20 % | Чек-лист из 20 пунктов m15-final плюс защита решения |

**Порог сдачи курса — 70 баллов из 100.**

Критерии самостоятельной работы: результат совпадает с эталоном по составу строк; не остались «мусорные» объекты; имена объектов соответствуют соглашению из раздела 5.1; требуемая заданием настройка действительно включена (например, каскадное удаление или условие на значение).

Критерии итогового проекта: 100 баллов распределяются так — данные 20, запросы 25, интерфейс 20, отчёты 15, автоматизация 10, эксплуатация 10; порог 70. Дополнительно к чек-листу проводится защита: короткая демонстрация сценария аналитика на собственном экземпляре базы по демо-маршруту из 7 шагов (модуль 15, секция control).

### 8.1. Шаблон теста модуля

- 6–8 вопросов; 4 варианта ответа; один или два верных (в JSON — массив correct).
- Обязательное пояснение к каждому вопросу; порог зачёта — 80 %; сохраняется лучший результат, ретейк доступен всегда.
- Не более трёх вопросов на «узнавание термина»; не менее половины — на выбор действия в ситуации.
- Запрещены вопросы вида «какая кнопка третья слева»: проверяется понимание, а не запоминание расположения элементов интерфейса.

## 9. Учёт версий Access 2007–2016

Основная версия курса — Access 2016: все шаги демонстраций описаны по её ленте. Там, где поведение отличается, в модулях стоят пометки «Для 2007–2013» (блок details.versions). Базовый формат файла — .accdb (появился в Access 2007); формат .mdb используется только как источник при импорте.

| Версия | Что важно для курса |
|---|---|
| 2007 | Лента и формат .accdb; вкладки документов (настраиваются); в макросах нет ветвления If — ветвление делают через VBA; экспорт PDF/XPS доступен как надстройка SP2 |
| 2010 | Ветвление If/Else и макросы данных (Data Macros); вычисляемые поля в таблицах; навигационные формы; TempVars; встроенный экспорт PDF/XPS |
| 2013 | Удалены проекты Access Data Projects (ADP); веб-приложения Access; в остальном совместим с материалами курса |
| 2016 | Поле «Что вы хотите сделать» (Tell Me); улучшенный диспетчер связанных таблиц; базовая версия для всех демонстраций курса |

Во всех версиях сохраняются: конструктор таблиц и запросов, SQL-режим, мастер отчётов, окно «Схема данных», редактор VBE. Учебник не опирается на функции, отсутствующие в 2007, за исключением отдельно помеченных модулей 11 и 12 (условия If в макросах, TempVars).

## 10. Сквозной проект ShopData: этапы по модулям

Датасет — интернет-магазин «ТехноДом» на основе Kaggle Olist Brazilian E-commerce. **7 таблиц**: Categories, Products, Customers, Employees, Orders, OrderDetails, Calendar. **6 связей**: Categories 1-М Products; Customers 1-М Orders; Employees 1-М Orders (по ManagerID); Orders 1-М OrderDetails (каскадное удаление); Products 1-М OrderDetails; Calendar 1-М Orders (по CalDate = OrderDate).
