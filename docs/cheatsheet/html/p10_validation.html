Проверка значений поля

Конструктор таблиц · тип «Короткий текст» · размер 40 · условие In (...) — допустимые значения проходят, «Прочее» отклоняется
Проверка срабатывает при вводе — в форме и прямо в таблице

Свойства поля в Конструкторе таблиц

Для поля Category задаётся тип «Короткий текст», ограничение длины и список разрешённых значений через условие In (...); значения внутри условия разделяются точкой с запятой.

Тип данныхКороткий текст

Сообщение об ошибке"Выберите категорию из списка"
Результат: Access проверяет каждое введённое значение ещё до сохранения записи — мусор в справочник не попадёт.

Как проходит проверка

Значение из списка — запись сохраняется; любое иное, включая «Прочее», Access отклонит и покажет сообщение.
вводимое значениепроверка In (...)
"Дом и мебель"✓ принято
"Красота и здоровье"✓ принято
"Электроника"✓ принято
"Авто"✓ принято
"Прочее"✗ отклонено
Результат: «Прочее» не входит в список In (...) — Access не даст сохранить запись, пока значение не исправят.

Проверка и SQL-ввод

Условие на значение действует и на INSERT — «запрещённую» строку запрос вставить не сможет.
Пример — допустимое значение
INSERT INTO Products (ProductName, Category)
VALUES ("Мышь", "Электроника");
Пример — отклоняемое значение
INSERT INTO Products (ProductName, Category)
VALUES ("Чехол", "Прочее");
запроситог
VALUES ("Мышь", "Электроника")✓ добавлено
VALUES ("Чехол", "Прочее")✗ нарушение

Зачем нужна проверка

Единый список категорий делает группировки и фильтры предсказуемыми: «Электроника» и «прочее» не размывают отчёты десятками вариантов.
Результат: GROUP BY Category даёт ровно четыре группы — отчёты сходятся со справочником.

Размер поля и длинные строки

Размер 40 ограничивает длину «Короткого текста»: строка длиннее 40 символов не сохранится.
Проверка длины выражением
WHERE Len([Category]) > 40
