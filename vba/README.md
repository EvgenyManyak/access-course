# VBA-примеры курса «Microsoft Access 2007–2016 для аналитика»

> 🚀 **Начало работы:** если вы ещё не подготовили рабочую среду и учебную базу ShopData.accdb, начните со страницы [../getting-started.html](../getting-started.html) — там собран весь маршрут (установка, папки, доверенное расположение, импорт стартового комплекта starter-data). Процедуры ниже предполагают готовую базу и без неё не запустятся.

Каталог `vba/` — приложение к учебнику: готовые, проверенные файлы кода VBA, которые разбираются в модулях 04 и 12–14 и используются в практических заданиях. Каждый `.bas` — самостоятельный текстовый файл с шапкой-комментарием, построчными комментариями на русском и обработкой ошибок `On Error GoTo ErrHandler`. Код писан под учебную базу ShopData (магазин «ТехноДом») из сквозного датасета курса.

| `calendar-generator.bas` (обычный модуль `modCalendarGenerator`) | `CreateCalendarTable`, `CreateCalendarByInsertLoop`, `CheckCalendar` | Создание и заполнение таблицы Calendar: 761 дата (01.10.2016 … 31.10.2018) через Recordset или учебный цикл INSERT, контрольные числа в Immediate. Подставьте свои имена, если они другие.

## Как открыть редактор VBA

Нажмите **Alt+F11** из любого окна Access (или: лента «База данных» → группа «Макрос и код» → **Visual Basic**). Полезные окна VBE:

- **Project Explorer** — Ctrl+R: дерево проекта, папки `Microsoft Access Class Objects` (формы) и `Modules` (обычные модули);
- **Properties** — F4: свойства выделенного модуля/формы;
- **Immediate** — Ctrl+G: окно немедленного выполнения выражений.

## Два способа добавить код

1. **Import File** — для обычных модулей: VBE → меню **File → Import File...** → выберите `export-examples.bas`, `import-examples.bas` или `calendar-generator.bas`. В Project Explorer появится готовый модуль целиком, с шапкой и Option Explicit. Это способ по умолчанию для файлов каталога.
2. **Копипаст в модуль** — откройте файл в блокноте (или прямо в VBE), скопируйте нужную процедуру и вставьте в существующий или новый модуль (**Insert → Module**). Единственный допустимый способ для `form-events.bas`: обработчики событий переносятся **только** в модули форм.

Примечание: файлы сохранены в UTF-8. Если после Import File русские комментарии выглядят наборкой символов, пересохраните файл в кодировке ANSI (Windows-1251) через Блокнот («Сохранить как» → «Кодировка») и импортируйте заново — сами команды VBA от этого не зависят.

## Обычный модуль vs модуль формы

| | Обычный модуль (Modules) | Модуль формы (Class Objects → Forms) |
|---|---|---|
| Как создать | Insert → Module или File → Import File... | Окно свойств формы (F4) → вкладка «События» → «...» → [Процедура обработки событий] |
| Что там живёт | самостоятельные процедуры: экспорт, импорт, переподключение, расчёты | обработчики событий: `Form_Load`, `Form_Current`, `btn..._Click`, `..._BeforeUpdate` |
| Доступ к форме | нет своего: объект формы передают аргументом | есть `Me` — текущая форма, её поля и элементы управления |
| События работают | нет: Access обработчики здесь не ищет | да: связь «событие → процедура» по имени |

Перенос обработчика события в обычный модуль — причина №1 ситуации «код вставлен, а кнопка молчит» (разбор в модуле 12, секция «Типичные ошибки»).

## Как запустить

- **F5** — курсор внутри процедуры, Run → Run Sub/UserForm; так запускаются процедуры обычных модулей (`ExportCategoryToXlsx`, `ImportExcelSheet`, `RefreshAllLinks`);
- **F8** — пошаговое выполнение: каждый оператор отдельно (Shift+F8 — шаг с заходом внутрь вызываемой процедуры пропускается);
- **кнопка на форме** — свойство кнопки «Нажатие кнопки» → [Процедура обработки событий]; обработчик (`btnImportCsv_Click`, `btnOpenOrders_Click`) должен лежать в модуле этой формы;
- **из Immediate** (Ctrl+G) — наберите имя процедуры и Enter; для процедуры из модуля формы — `Forms!frm_Заказы.ShowStats_Immediate` (форма должна быть открыта);
- **RefreshAllLinks** удобно вызывать из Immediate с параметром: `RefreshAllLinks "C:\ShopData\shopdata_be.accdb"`.

## Отладка

- **Immediate (Ctrl+G)** — быстрый калькулятор и «печать»: `? DCount("*", "Orders")` выполняет выражение после `?` и печатает результат ниже; всё, что отправляет `Debug.Print`, попадает сюда же;
- **Debug.Print** в коде — контрольные значения при выполнении (см. `ShowStats_Immediate`): строка печатается в Immediate и не останавливает программу;
- **Locals** (Вид → Окно локальных значений) — на паузе показывает все переменные текущей процедуры и их значения: удобнее, чем десяток Debug.Print;
- **точки останова F9** — щёлкните слева от строки (или F9 на ней): выполнение дойдёт до строки и встанет; дальше — F8 по шагам, значения смотрите в Locals и наведением мыши на переменную;
- снять точку останова — повторное F9; сбросить всё сразу — Run → Reset.

## Правила именования

- Имена процедур событий Access задаёт сам: `ИмяЭлемента_ИмяСобытия` — `Form_Load`, `Form_Current`, `btnImportCsv_Click`, `UnitPrice_BeforeUpdate`. Переименуете вручную — связь с событием порвётся.
- Стиль `btn_..._Click` с подчёркиванием после префикса не обязателен: курс использует слитные имена `btnImportCsv`, `btnOpenOrders`. Главное — единый стиль во всём проекте, а не конкретный шаблон.
- Собственные процедуры — глагол + существительное: `ExportQueryToCsv`, `ImportExcelSheet`, `RefreshAllLinks`.
- Объекты Access — по соглашению курса: префиксы `qry_` (запросы), `frm_` (формы), `sfrm_` (подчинённые формы), `rpt_` (отчёты), `mcr_` (макросы); таблицы — без префикса.
- Переменные — короткие с типовым префиксом: `strFile`, `lngFiles`, `db`, `rs`, `tdf`; константы — `SPEC_NAME` (верхний регистр с подчёркиванием).
- `Option Explicit` обязателен: каждая переменная объявлена `Dim`/`Const`. Включите требование объявления переменных: VBE → Tools → Options → Editor → флажок Require Variable Declaration.

## Макробезопасность

При первом открытии базы с кодом Access показывает жёлтую панель «Предупреждение системы безопасности» — нажмите **Включить содержимое**, иначе VBA отключён: F5 не работает, события кнопок молчат. Настройка на постоянку: **Файл → Параметры → Центр управления безопасностью → Параметры центра управления безопасностью → Надёжные расположения** — добавьте папку с учебной базой, и панель в ней больше не появится. Для чужих файлов кнопку полного отключения проверок не используйте — код неизвестного происхождения выполняйте только осознанно.

## Типовые ошибки компиляции

| Сообщение VBE | Причина | Что проверить |
|---|---|---|
| Variable not defined | стоит `Option Explicit`, а переменная не объявлена или опечатана | `Dim` в начале процедуры; совпадение имён (`lngFiles` и `lngFile` — разные переменные) |
| Sub or Function not defined | вызов процедуры с опечаткой или сломанной библиотеки | точность имени; Tools → References — нет ли строки «MISSING: ...» |
| Expected: end of statement | два оператора в одной строке либо перенос строки без « _» | перенос длинной строки — пробел и подчёркивание в конце первой строки |
| Block If without End If | блочный `If...Then` не закрыт | каждому блочному `If` — свой `End If`; каждой процедуре — `End Sub`/`End Function` |
| Invalid outside procedure | исполняемый код вставлен вне процедуры | весь код — внутри `Sub`/`Function`; снаружи допустимы только объявления уровня модуля (`Option`, `Dim`, `Const`) |
| Ambiguous name detected | в одном модуле два одинаковых имени | удалите дубликат (частый случай — процедура вставлена второй раз) |
| Else without If | `Else` добавлен к однострочному `If ... Then действие` | однострочный `If` не продолжается блоком `Else`; перепишите в блочную форму |
| Can't find project or library | ссылка на библиотеку не подключена | Tools → References: снять и заново поставить галочку у проблемной библиотеки |

Ошибки времени выполнения ловит обработчик: MsgBox вида «Ошибка 3051: ...». Сначала читайте номер (`Err.Number`) и описание (`Err.Description`), затем сверяйтесь с комментарием над меткой `ErrHandler` — там перечислены частые причины именно этой процедуры.
