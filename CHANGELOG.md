## [1.1.2] — 2026-09-22

### Исправлено

- **Модуль 05: пошаговая демонстрация дедупликации вводила в заблуждение и ломалась на шагах 3–6.**
  Мастер «Поиск повторяющихся записей» строит список всех копий (в сценарии — 6 строк,
  по две на C-0002/C-0003/C-0007, без колонки ЧислоПовторов), а модуль приписывал ему
  агрегат GROUP BY/HAVING (3 строки). Из-за этого соединение Customers_Staging с
  мастер-запросом давало 12 строк в превью вместо 6, Access отказывался удалять, и весь
  конвейер вставал. Новый рецепт: мастер — только быстрый просмотр; сводка повторов
  (qry_ПовторыCustomerID, 3 строки) студент строит сам; запрос на удаление — одна
  таблица и условие `In (SELECT CustomerID FROM qry_ПовторыCustomerID)`, без соединений
  и линий. Все контрольные числа (11 → −6 → 5 → +3 → 8) сохранены.
- Линия в конструкторе запросов объяснена: это JOIN внутри конкретного запроса, а не
  связь схемы данных; целостность она не проверяет. В запросе на удаление линий нет.
- Шаг «бонус» (поиск записей без пары) переписан на ручное левое соединение
  Employees ↔ Orders (EmployeeID/ManagerID) с Is Null — мастер несоответствий упоминается
  как альтернатива, поскольку пара полей имеет разные имена.
- Промежуточность данных: Customers_Staging от модуля 04 (6 строк другого состава) не
  подходит модулю 05 — добавлен шаг подготовки с пересозданием таблицы.

### Добавлено

  11 строк (8 уникальных покупателей + полные дубли C-0002/C-0003/C-0007 + грязь

### Изменено

## [1.1.1] — 2026-09-18

### Исправлено

- **Мобильное меню (бургер ☰) не раскрывалось по нажатию на сенсорном экране.**
  Причины: (1) открытая панель сайдбара (z-index 100) и затемняющий фон (z-index 90)
  перекрывали кнопку в шапке (z-index 80) — повторное и часть первых нажатий
  приходились на панель/фон, а не на кнопку; (2) состояние держалось только на
  классе body.nav-open без классов состояния на кнопке и меню, без ARIA-атрибутов
  и без резервного обработчика на самой кнопке; (3) `.icon-btn { display:inline-flex }`
  в каскаде перебивал `.topbar__burger { display:none }` — бургер был виден и на
  десктопе, где меню и так открыто.

### Изменено

- `js/app.js`: кнопке меню задан эталонный id `menuToggle` + `aria-expanded`,
  `aria-controls="courseMenu"`, динамический `aria-label`; сайдбар получил
  id `courseMenu` и управление `aria-hidden`.
- `js/navigation.js`: единая машина состояний меню — openMenu/closeMenu/toggleMenu
  (`.is-open` на меню, `.is-active` на кнопке, `body.nav-open` для фона и блокировки
  прокрутки); прямой обработчик click на кнопке с stopPropagation (делегирование
  сохранено как резерв); закрытие по клику вне меню, по Escape с возвратом фокуса
  на кнопку, по выбору пункта; сброс состояния при переходе к ширине > 1024px;
  диагностический console.error при отсутствии элементов.
- `css/styles.css`: `.topbar .topbar__burger { display:none }` повышенной
  специфичности — бургер снова скрыт на десктопе.
- `css/responsive.css`: слои фон (90) < шапка (95) < панель (100) < бургер (1100);
  панель раскрывается под шапкой (top: var(--topbar-h)); плавная анимация
  transform + visibility (0.25s) и fade фона; `touch-action: manipulation` и
  подсветка нажатия убраны; видимое состояние `.topbar__burger.is-active`.
- Пересобраны standalone.html и access-course-project.zip (80 файлов).

## [1.0.0] — 2026-09-15

Первый публичный релиз учебника.

### Добавлено

- **Курс:** 15 модулей Microsoft Access 2007–2016 (единая структура из 17 секций),
  80 академических часов, 20 практических заданий E01–V02 на сквозном датасете
  ShopData (основа — Kaggle Olist Brazilian E-commerce), итоговый проект
  с 20-пунктовым чек-листом сдачи.
- **Интерфейс:** сайдбар с оглавлением модуля и scrollspy, кликабельное оглавление,
  «Назад/Далее», индикатор прогресса, полнотекстовый поиск по всему курсу,
  светлая и тёмная темы, раскрывающиеся решения (details), блоки «Важно» /
  «Типичная ошибка» / «Практический совет», интерактивные чек-листы,
  тесты 6–8 вопросов с пояснениями и порогом 80%, клавиатурная навигация
  (← → / Ctrl+K / Esc), адаптивная вёрстка, поддержка кириллицы.
- **Экспорт (8 действий):** печать/PDF с титульной страницей и оглавлением,
  скачивание HTML раздела, экспорт модуля и всего курса в Markdown,
  экспорт модуля и всего курса в TXT, копирование раздела и всего курса
  в буфер обмена; экспорт «весь курс» работает офлайн за счёт зашитого
  кэша содержимого (COURSE_CACHE в js/export.js).
- **Данные:** каталог datasets/ — кликабельные ссылки Kaggle с лицензиями
  и датами проверки (Olist — основной; Superstore и Online Retail —
  альтернативы; непроверенная ссылка помечена TODO: VERIFY DATASET URL),
  словарь данных, инструкции импорта (3 пути, включая мини-датасет без Kaggle).
- **Код-примеры:** 6 файлов Access SQL (выборки, соединения, агрегаты,
  параметры, перекрёстные, action-запросы) и 3 файла VBA + README
  (экспорт, импорт и переподключение связанных таблиц, события форм).
- **Схемы:** 4 SVG — ER-диаграмма ShopData, поток данных CSV→отчёт,
  разделение BE/FE, последовательность макроса.
- **Документация:** программа курса, чек-лист студента, руководство
  преподавателя, гайд по тестированию (18 пунктов).
- **Инфраструктура:** standalone.html (весь курс в одном файле), скрипты
  build-zip.ps1 и build-zip.sh, .gitignore, LICENSE (MIT + примечания
  о датасетах), README (18 разделов), favicon и логотип.

### Особенности реализации

- Чистые HTML + CSS + JavaScript, без зависимостей и сборочных инструментов;
  работает по file:// и на GitHub Pages.
- Прогресс, результаты тестов и чек-листы — в localStorage (ключи ac.*).
- Подсветка SQL/VBA — собственный токенайзер (без внешних библиотек).
- Версионирование контента: манифест модулей — js/app.js (AC.MANIFEST);
  добавление модуля — копия страницы + запись в манифест.

### Известные ограничения

- Прогресс не синхронизируется между устройствами; поиск ищет по кэшу,
  который нужно пересобирать после правок модулей; номера страниц в PDF
  проставляет браузер (опция «Колонтитулы»); DOCX/XLSX в браузере не
  генерируются (в панели экспорта даны инструкции по конвертации).
