Зачем эта страница

Это единственное место, где собраны все подготовительные шаги курса. Пройдите её сверху вниз — и к концу у вас будет работающая база ShopData.accdb с шестью таблицами, ключами, связями и проверенным первым запросом. Искать инструкции по папкам проекта не придётся: здесь есть ссылки на все нужные файлы, а спорные места разобраны в разделе ошибок. Дополнительные подробные документы — чек-лист импорта, словарь данных и расширенная версия этой инструкции — лишь углубляют то, что описано здесь.

Курс живёт на сквозном датасете ShopData (интернет-магазин). Для старта не нужен Kaggle: в папке starter-data/ лежат шесть готовых CSV — категории (5 строк), товары (8), покупатели (8), сотрудники (6), заказы (12), позиции заказов (15). Все контрольные числа модулей 01–15 выверены по этому комплекту: любой «Ожидаемый результат» курса сходится построчно.

Два маршрута

Быстрый (рекомендуется): стартовый комплект из starter-data/ — без загрузок со стороны, 30–40 минут на всё. Полный: большой датасет Olist с Kaggle (100 тыс. заказов) — подключается позже, в модуле 04, по инструкции datasets/import-instructions.md (путь А). Мини-датасет полностью совместим с заданиями курса: когда позже импортируете большой датасет, задания курса выполняются на любой из двух баз.

Шаг 1. Программное обеспечение и версии

Курс построен на настольном Access для Windows — веб-версий и версий для Mac у этого продукта нет, поэтому начните с проверки окружения. Показанный в учебнике интерфейс — Access 2016, но отличия 2007–2013 описаны в каждом модуле, а лента и мастер импорта за десять лет менялись мало: на 2007-м и 2010-м курс проходили без изменений маршрутов.

Шаг 2. Рабочая папка

Создайте папку курса и четыре подпапки — такая структура используется во всех модулях, а в модуле 14 станет back-end/front-end каркасом:

C:\Courses\ShopData\
├── import\    ← сюда копируйте CSV (стартовый комплект и позже — выгрузки Olist)
├── base\      ← здесь будет база ShopData.accdb
├── export\    ← сюда модули 11 и 13 пишут выгрузки XLSX/CSV/PDF
└── backup\    ← резервные копии базы (шаг 13 этой страницы)

Создать можно Проводником или одной командой PowerShell (Пуск → наберите «PowerShell» → Enter):

md C:\Courses\ShopData\import, C:\Courses\ShopData\base, C:\Courses\ShopData\export, C:\Courses\ShopData\backup

Буква диска и путь могут быть любыми — главное, чтобы путь не содержал кириллицы и пробелов: некоторые мастера экспорта и VBA-примеры курса передают пути как строки, и «C:\Пользователи\…» периодически ломает кавычки. Папка на сетевом диске или OneDrive для учебной базы тоже нежелательна: Access чувствителен к задержкам синхронизации и может повредить файл при одновременной записи.

Шаг 4. Проверка целостности и кодировки

Перед импортом убедитесь, что файлы доехали без искажений — три минуты на весь комплект. Курсы данных ломаются чаще всего на пересохранении «удобной» программой, поэтому проверка — обязательный шаг, а не перестраховка.

  1. Откройте в Проводнике папку с файлами и сверьте размеры: categories ≈ 0,3 КБ, products ≈ 0,6 КБ, customers ≈ 0,5 КБ, employees ≈ 0,5 КБ, orders ≈ 0,8 КБ, order-details ≈ 0,8 КБ, calendar ≈ 38 КБ. Файл нулевого размера или «битый» архив перекачайте.
  2. Откройте customers.csv в Блокноте: первая строка — заголовок CustomerID,CustomerName,ZipCodePrefix,City,State,Segment, вторая — C-0001,Ana Ribeiro,01310,sao paulo,SP,Retail. Кириллица должна читаться (она есть в products.csv: «Набор постельного белья 2-сп») — если вместо неё кракозябры, файл был пересохранён не в UTF-8: скачайте заново.
  3. Посчитайте строки одной командой PowerShell (подставьте имя файла): (Get-Content C:\Courses\ShopData\import\customers.csv).Count — ожидается 9 (заголовок + 8 строк). Для остальных: categories 6, products 9, employees 7, orders 13, order-details 16, calendar 762.
  4. В Excel (если установлен) откройте файл через «Данные → Из текста/CSV» и убедитесь, что даты вида 2017-03-15 и цены 189.90 отображаются как есть. Закройте Excel без сохранения.
Что именно проверяем

Формат комплекта: UTF-8 с BOM, переводы строк CRLF, разделитель — запятая, даты ISO (ГМД), цены с точкой. Такой выбор совпадает с форматом большого датасета Olist и файлом calendar.csv: одна настройка мастера импорта работает для всех файлов курса сразу.

Шаг 5. Доверенное расположение, содержимое и системные объекты

Access намеренно блокирует «подозрительные» базы: любые макросы, VBA и часть мастеров не работают, пока файл не в доверенной папке. Мы один раз добавляем рабочую папку в доверенные — и все базы из неё открываются без предупреждений.

  1. Откройте Access (пустую базу можно не создавать) → Файл → Параметры → Центр управления безопасностью → Параметры центра управления безопасностью… → Доверенные расположения.
  2. Нажмите «Добавить новое расположение» → «Обзор» → выберите C:\Courses\ShopData\ → ОК. Галочку «Разрешить расположения в сети (не рекомендуется)» не включайте.
  3. При открытии базы, если впервые увидели жёлтую полосу «ПРЕДУПРЕЖДЕНИЕ СИСТЕМЫ БЕЗОПАСНОСТИ. Включить содержимое» — нажмите «Включить содержимое». После добавления доверенного расположения полоса появляться не должна.
  4. Проверка: положите в base\ любую базу и откройте — полосы безопасности быть не должно, а в модуле 12 макросы и VBA запустятся без вопросов.

Системные объекты (таблицы MSys*) по умолчанию скрыты — и это хорошо: курс упоминает их только один раз, в модуле 14 при разговоре о сжатии. Включать их нужно, лишь если вы хотите увидеть служебные таблицы Access своими глазами: правый щелчок по заголовку области навигации → «Параметры навигации…» → отметить «Показывать системные объекты». Ничего в MSys-таблицах не изменяйте — это «механизм» Access, а не ваши данные; после изучения верните галочку обратно.

Почему не стоит доверять «всему компьютеру»

Добавляйте в доверенные только конкретные учебные папки. Кнопка «Включить содержимое» в файле из интернета означает «я знаю этот источник» — привычка включать всё подряд сводит защиту Access к нулю, а VBA умеет удалять файлы так же уверенно, как и строить отчёты.

Шаг 6. Пустая база данных

  1. Запустите Access → на стартовом экране выберите «Пустая база данных рабочего стола» (в 2016 — просто «Пустая база данных»).
  2. В поле «Имя файла» введите ShopData.accdb.
  3. Щёлкните значок папки рядом с именем, выберите C:\Courses\ShopData\base\ и нажмите «Создать».
  4. Access откроет пустую базу с заготовкой «Таблица1» в режиме таблицы. Закройте её правым щелчком по вкладке → «Закрыть», на вопрос о сохранении ответьте «Нет» — структуру таблиц мы задаём импортом и конструктором, а не пустым листом.
  5. Сверьтесь с областью навигации слева: заголовок «Все объекты Access», под ним пока пусто (или только «Таблица1»). Файл уже лежит в base\ — это видно в заголовке окна Access.

Имя базы принципиально только для порядка в материалах: все инструкции курса говорят «откройте ShopData.accdb». Расширение .accdb — формат Access 2007+; в формате 2003 (.mdb) не будет вычисляемых полей и части типов — если Access предложил «формат 2002–2003», смените на «База данных рабочего стола Access 2007–2016».

Шаг 7. Импорт шести CSV

Процедура одинакова для всех шести файлов: пройдите её первый раз по шагам ниже (показано на categories.csv), остальные — по компактной таблице. Порядок: categories → products → customers → employees → orders → order-details — справочники раньше фактов, тогда при проверке связей каждой ссылке будет на что смотреть.

  1. Вкладка «Внешние данные» → группа «Импорт и связи» → «Новый источник данных» → «Из файла» → «Текстовый файл».
  2. Укажите C:\Courses\ShopData\import\categories.csv, выберите «Импортировать исходные данные в новую таблицу» → ОК.
  3. Мастер, шаг 1: «С разделителями — символы, например запятая или знаки табуляции, отделяют значения полей» → Далее.
  4. Шаг 2: разделитель — «запятая», ограничитель текстов — ", «Первая строка содержит названия полей» — отмечено. Нажмите «Дополнительно…» и в поле «Порядок дат» выберите ГМД (год-месяц-день — так хранятся даты во всех файлах курса) → ОК → Далее.
  5. Шаг 3: Access предлагает поля и типы. Сверьте с таблицей ниже; здесь для categories оставьте как есть → Далее.
  6. Шаг 4: выберите «Самостоятельно задать первичный ключ» → в списке полей — CategoryID → Далее.
  7. Шаг 5: имя таблицы Categories → «Готово». Окно «Сохранить шаги импорта» можно закрыть (вернёмся к спецификациям в модуле 13).
  8. Повторите шаги 1–7 для остальных пяти файлов, сверяя поля и типы с таблицей. Ключ поля и обязательные типы — в последней колонке.

Шаг 8. Проверка типов данных после импорта

Мастер угадывает типы по первым строкам, поэтому финальная проверка — глазами, в конструкторе. Для каждой из шести таблиц: правый щелчок по таблице → «Конструктор» → сверьте колонку «Тип данных» со словарём (кратко — таблица шага 7, подробно — data-dictionary.md). Обратите внимание на три классических места, где Access ошибается чаще всего.

  • ZipCodePrefix должен быть текстом (5). Если мастер выбрал числовой — у C-0001 вместо 01310 стало 1310. Лечение: переимпорт с ручным типом (самый надёжный) или через конструктор смените тип на «Короткий текст» и верните ноль запросом UPDATE Customers SET ZipCodePrefix = Format([ZipCodePrefix],"00000").
  • Даты должны быть типа «Дата/время»: значение выровнено вправо, при щелчке по ячейке справа появляется значок календаря. Текстовые даты выровнены влево — вернитесь к шагу «Дополнительно… → ГМД» при переимпорте.
  • Деньги (UnitPrice, FreightValue) — тип «Денежный», в ячейках «1 899,00 р.» на русской локали. Если поле осталось текстом (значения слева), используйте решение из import-checklist.md (ошибка № 4): новое денежное поле + UPDATE … SET Поле = CCur(Val([СтароеПоле])) — функция Val читает точку независимо от локали.

Зачем это раньше времени: типы, поставленные сейчас, определяют, сработают ли связи (шаг 10) и посчитаются ли контрольные суммы. Модуль 02 объяснит каждый тип системно — здесь достаточно «текст/число/дата/деньги/логический».

Шаг 9. Первичные ключи

Ключ вы задавали в мастере (шаг «Самостоятельно задать первичный ключ»), но проверьте значок ключа в конструкторе каждой таблицы: Categories — CategoryID, Products — ProductID, Customers — CustomerID, Employees — EmployeeID, Orders — OrderID, OrderDetails — OrderDetailID. Если значка нет: выделите строку поля (серый квадрат слева) → вкладка «Конструктор» → «Ключевое поле» → Ctrl+S.

Быстрый тест ключа: откройте Orders в режиме таблицы и попробуйте ввести новый заказ с тем же кодом O-10001 — Access обязан отклонить запись сообщением «Изменения не были успешно внесены из-за повторяющихся значений…». Отмените ввод клавишей Esc. Это же правило — «ключ уникален и не пуст» — позволит строить связи на следующем шаге.

Ключи-счётчики: в схеме курса CategoryID, EmployeeID и OrderDetailID объявлены типом «Счётчик». В импортированной таблице они числовые со значениями из файлов — на задания курса это не влияет (значения 1–5, 1–6 и 1–15 совпадают со счётчиком один в один). Переводить поле в «Счётчик» вручную не нужно: Access разрешает смену типа только на пустой таблице, а повторный импорт ради этого не стоит.

Шаг 10. Связи между таблицами

Откройте «Работа с базами данных» → «Схема данных», добавьте все шесть таблиц (Ctrl+щёлчок по списку) и растяните их так, чтобы справочники были сверху. Затем пять раз повторите одно и то же: перетащите мышью поле-ключ из одной таблицы на поле другой, в окне «Изменение связей» отметьте «Обеспечение целостности данных» и нажмите «Создать».

Шаг 11. Проверка ссылочной целостности

Целостность — это не галочка, а поведение базы. Проверьте его руками — одна минута:

  1. Откройте Orders в режиме таблицы. В строке любого заказа попробуйте вписать в ManagerID значение 9 — сотрудников только шестеро. Access должен показать ошибку «Введенное значение не может быть сохранено… требуется связанная запись в таблице Employees». Нажмите Esc.
  2. Попробуйте в OrderDetails ввести позицию с OrderID = O-99999 — та же реакция: такой заказ не существует. Esc.
  3. Вернитесь в Схему данных: у каждой линии с целостностью Access показывает «1» и знак бесконечности — символы «один ко многим».

Если база позволила ввести «мусор» — связь создана без «Обеспечения целостности данных» либо вообще не создана: вернитесь к шагу 10. Это упражнение — уменьшенная копия того, что в модуле 05 станет регулярной дисциплиной очистки данных.

Шаг 12. Первый тестовый запрос и контрольные числа

Время показать, что база «живая». Создание → Конструктор запросов → закройте окно «Добавление таблицы» → правый щелчок по вкладке → «Режим SQL». Вставьте первый запрос курса и выполните кнопкой с восклицательным знаком:

SELECT TOP 5 CustomerID, CustomerName, City, Segment
FROM Customers
ORDER BY CustomerID;

Ожидается ровно пять строк: C-0001 Ana Ribeiro (sao paulo, Retail), C-0002 Bruno Carvalho, C-0003 Carla Mendes, C-0004 Diego Silva, C-0005 Elena Costa. Сохраните запрос как qry_КлиентыТоп5 — так курс и советует: рабочие запросы живут в базе, а не в блокноте. Полный разбор этого запроса — в модуле 01.

Главный интеграционный тест курса — выручка по категориям без отменённых (эталон модуля 08):

SELECT c.CategoryNameEn,
       ROUND(SUM(od.UnitPrice * od.Quantity), 2) AS Выручка
FROM Categories AS c
INNER JOIN (Products AS p
            INNER JOIN (Orders AS o
                        INNER JOIN OrderDetails AS od
                        ON o.OrderID = od.OrderID)
            ON p.ProductID = od.ProductID)
ON c.CategoryID = p.CategoryID
WHERE o.OrderStatus <> "canceled"
GROUP BY c.CategoryNameEn
ORDER BY SUM(od.UnitPrice * od.Quantity) DESC;

Ожидается 5 строк: bed_bath_table 769.50 · computers_accessories 746.50 · furniture_decor 640.00 · health_beauty 631.50 · automotivo 238.00 — итого 3025.50. Если все четыре проверки сошлись — данные, типы, ключи и связи корректны: любую цифру курса вы теперь можете воспроизвести.

Шаг 14. Резервное копирование

Файл Access — это один .accdb-контейнер со всем: таблицами, запросами, формами и кодом. Повредить его можно закрытым ноутбуком в момент записи, «замороженным» OneDrive или экспериментом с DELETE — поэтому копия делается до, а не после. Для учебной базы достаточно простого правила.

  1. Перед каждым рискованным шагом (action-запросы модуля 08, разделение базы в модуле 14): закройте Access и скопируйте base\ShopData.accdb в backup\, добавив дату в имя: ShopData_2026-09-17.accdb.
  2. Раз в неделю или после «сессии» с курсом — такая же копия независимо от планов.
  3. Штатное средство: Файл → «Сохранить как» → «Сохранить базу данных как» → «База данных Access» — Access создаст копию и предложит открыть её; для учебных целей копия Проводником проще и не меняет активную базу.
  4. Сжатие перед копированием: Файл → «Сведения» → «Сжать и восстановить» — уменьшает файл и «пересобирает» внутренние индексы. Автосжатие при закрытии включается там же: Параметры → Текущая база данных → «Сжать при закрытии».

Модуль 14 построит из этого привычку систему: разделение back-end/front-end, копирование только таблиц-данных, журнал резервирования. Пока — одна папка backup\ и дисциплина имени с датой.
