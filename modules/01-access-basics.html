Модуль 01Access для аналитика: отличие от Excel и SQL

Блок A. Основы и данные ⏱ 3 ч (2 Т + 1 П) Базовый уровень

Цели обучения

Модуль открывает курс и задаёт рамку: мы разбираем, зачем аналитику отдельный инструмент для баз данных, и делаем первые шаги в Access 2016. По итогам модуля студент сможет:

  • объяснить заказчику, в каких задачах Access эффективнее Excel, а в каких уместнее серверные СУБД (SQL Server, PostgreSQL), опираясь на критерии объёма, целостности и числа пользователей;
  • назвать шесть типов объектов базы Access — таблицы, запросы, формы, отчёты, макросы, модули VBA — и рассказать, за что отвечает каждый;
  • уверенно ориентироваться в интерфейсе Access 2016: лента с контекстными вкладками, область навигации, вкладки документов, режим Backstage и окно «Файл → Параметры»;
  • открыть учебную базу, создать первую таблицу Categories с пятью категориями сквозного датасета ShopData и выполнить первый запрос SELECT TOP 5 к таблице Customers.

Необходимые предварительные знания

Модуль рассчитан на старт «с нуля» в части баз данных, но предполагает уверенную работу за компьютером. Никакого опыта с СУБД не требуется: если вы умеете сводить данные в Excel и понимать смысл столбцов и строк, этого достаточно. Пригодится, но не обязательно, начальное знание SQL — хотя бы интуиция, что SELECT «выбирает» строки из таблицы. Тем, кто знает SQL в другом диалекте (MySQL, T-SQL), модуль поможет перестроиться на особенности Access.

  • Windows: работа с файлами и папками, умение создать папку для учебных материалов.
  • Excel базового уровня: формулы, сортировка, фильтры, понимание «плоской» таблицы данных.
  • Желательно: установленный Microsoft Access 2007–2016 (в курсе показан интерфейс Access 2016).
  • Опционально: любой опыт с SQL — он ускорит прохождение разделов про запросы.
Важно

Если Excel для вас terra incognita или вы впервые открываете Windows-приложения с лентой, сначала пройдите короткий вводный курс по Excel (1–2 часа достаточно). Без базовой привычки к таблицам «строка–столбец» модули 02–05 пойдут заметно тяжелее, и экономия времени на подготовке обернётся потерями дальше.

Теория

Microsoft Access — это одновременно хранилище данных и среда разработки, упакованные в один файл. Файл с расширением .accdb (формат действует с версии 2007) является контейнером объектов: в нём живут и данные, и инструменты для работы с ними. Движок базы данных — ACE (Access Database Engine), преемник Jet, — встроен в Access и отвечает за чтение и запись данных, контроль типов, ключей и связей. Для аналитика это означает, что полноценное приложение с данными можно унести на флешке и открыть на другом компьютере без установки серверов.

Внутри контейнера живут шесть типов объектов. Таблицы хранят данные в строках и столбцах с жёстко заданной схемой — в нашем курсе их семь (Customers, Products, Categories, Orders, OrderDetails, Employees, Calendar). Запросы задают данные вопросы: фильтруют, соединяют таблицы, считают суммы; каждый запрос — это сохранённый SQL-текст, который можно запускать повторно. Формы дают удобный экран ввода, отчёты — аккуратную печать и экспорт в PDF, макросы — автоматизацию без программирования, а модули VBA — полноценный код на Visual Basic for Applications. Один и тот же файл Access объединяет всё: данные, расчёты, интерфейс и автоматизацию.

  • Таблицы — хранилище; каждая сущность (клиент, товар, заказ) — отдельная таблица.
  • Запросы — отбор, соединение и агрегация; сохраняются под именем (в курсе — с префиксом qry_).
  • Формы — ввод и навигация (префикс frm_, подчинённые — sfrm_).
  • Отчёты — печать и PDF (префикс rpt_).
  • Макросы — кнопочная автоматизация (префикс mcr_).
  • Модули VBA — программный код для сложных сценариев.

Когда Access лучше Excel? Первое — объём: лист Excel ограничен 1 048 576 строками и ощутимо тормозит уже на десятках тысяч, тогда как файл Access хранит до 2 ГБ данных и спокойно работает с сотнями тысяч строк. Второе — дисциплина данных: в Excel столбец не имеет типа, поэтому «01310» превращается в «1310», а дата «03.15» молча становится текстом; в Access тип закреплён за полем, и мусор не проходит. Третье — целостность: Access умеет запрещать заказы без клиента и позиции без заказа. Четвёртое — совместная работа: несколько человек одновременно могут вводить данные в одну базу по сети. Пятое — повторяемость: еженедельный отчёт в Excel пересобирается руками, в Access — одной кнопкой по сохранённому запросу.

Когда нужен «большой брат» — SQL Server или PostgreSQL? Если пользователей сотни и они заходят через веб, если история измеряется гигабайтами и терабайтами, если нужны транзакции серверного уровня и круглосуточная доступность — это территория серверных СУБД. При этом Access часто остаётся удобным интерфейсом к серверу: таблицы переносятся на сервер, а запросы, формы и отчёты остаются в Access-файле и работают со связанными таблицами. Такой гибрид — типовая архитектура отделов, доросших до Excel, но не доросших до выделенной команды разработки.

Интерфейс Access 2016 устроен так: сверху — лента с вкладками «Файл», «Главная», «Создание», «Внешние данные», «Работа с базами данных», к которым добавляются контекстные вкладки (например, «Конструктор» у открытой таблицы). Слева — область навигации, оглавление базы, где сгруппированы все объекты. Каждый объект открывается во вкладке документа, как листы в браузере. Вкладка «Файл» открывает режим Backstage — полноэкранное меню создания, открытия, печати и параметров базы; в частности, «Файл → Параметры → Текущая база данных» управляет стартовой формой и автосжатием, а «Файл → Параметры → Центр управления безопасностью» — включением содержимого базы.

Для 2007–2013: отличия интерфейса и возможностей

Курс построен на Access 2016, но материал применим к версиям 2007–2016: ядро (таблицы, запросы, конструкторы, SQL) почти не менялось. Ниже — значимые отличия, о которых стоит помнить, работая на старых версиях.

  • 2007. Появились лента, область навигации (вместо окна базы Access 2003) и формат .accdb; файлы .mdb по-прежнему открываются, но в них недоступны новые типы полей (вложение, вычисляемый, поле многозначного подстанова).
  • 2010. Макросы получили условия If/Иначе и коллекцию TempVars, в таблицах появились вычисляемые поля; обновился дизайнер форм.
  • 2013. Удалены проекты ADP (прямое подключение Access к SQL Server «поверх таблиц»); веб-базы 2010 года заменены Access-приложениями, которые к 2018 году были закрыты — на них не стоит строить учебные решения.
  • 2016. На ленте появилось поле «Расскажи мне, что вы хотите сделать» (Tell Me) для быстрого поиска команд; вернулась поддержка dBASE в импорте и экспорте.

Пошаговая демонстрация

Пройдём первый сеанс работы с Access: откроем учебную базу, осмотримся в интерфейсе и создадим первую таблицу — справочник категорий Categories из сквозного датасета ShopData. Если материалы курса содержат готовый файл shop_start.accdb, используйте его; если нет — создадим базу с нуля, на это уйдёт пара минут.

  1. Запустите Access 2016. На стартовом экране справа отображается список недавних баз; слева — шаблоны. Если шаблоны вам не нужны, сразу переходите к шагу 2.
  2. Выберите шаблон «Пустая база данных». В правой части экрана в поле «Имя файла» введите ShopData.accdb, щёлкните значок папки, выберите отдельную папку для курса (например, C:\Courses\access) и нажмите кнопку «Создать».
  3. Access откроет новую базу: появится пустая таблица «Таблица1» в режиме таблицы, слева — область навигации, сверху — лента. Пока ничего не вводите: в режиме таблицы Access угадывает типы полей, а мы хотим задать их сами.
  4. Осмотритесь. Разверните в области навигации заголовок «Все объекты Access» — там перечислены объекты базы. Откройте вкладку «Файл»: это Backstage; вернитесь кнопкой со стрелкой «Назад».
  5. Если вы работаете с учебным файлом shop_start.accdb, откройте его через «Файл → Открыть → Обзор», найдите файл и нажмите «Открыть». В базе уже есть 7 таблиц ShopData — их список виден в области навигации.
  6. Создадим первую таблицу. На ленте откройте вкладку «Создание» и в группе «Таблицы» нажмите «Конструктор таблиц». Откроется пустой бланк конструктора: строки полей сверху, «Свойства поля» снизу.
  7. В первой строке задайте имя поля CategoryID, тип «Счётчик». Во второй — CategoryName, тип «Короткий текст», в свойствах снизу установите «Размер поля» = 64. В третьей — CategoryNameEn, тоже «Короткий текст» размером 64.
  8. Выделите строку CategoryID целиком (щёлкните серый квадрат слева от имени) и нажмите на вкладке «Конструктор» в группе «Сервис» кнопку «Ключевое поле». Слева от строки появится значок ключа: Access понял, что это первичный ключ.
  9. Сохраните таблицу: Ctrl+S, в окне «Сохранение» введите имя Categories и нажмите «ОК». Таблица появится в области навигации.
  10. Переключитесь в режим ввода данных: вкладка «Главная → Вид → Режим таблицы». Внесите пять категорий мини-датасета: cama_mesa_banho / bed_bath_table, beleza_saude / health_beauty, informatica_acessorios / computers_accessories, moveis_decoracao / furniture_decor, automotivo / auto. Поле CategoryID оставляйте пустым — счётчик заполнит его сам значениями 1–5.
  11. Данные сохраняются автоматически при переходе на другую запись — кнопки «Сохранить», как в Excel, для строк не требуется. Закройте вкладку таблицы и снова взгляните на область навигации: база обзавелась первым собственным объектом.
Практический совет

Значение поля «Счётчик» Access присваивает сам и не позволяет его редактировать в режиме таблицы. Не пытайтесь «исправить» нумерацию: счётчик нужен для уникальности, а не для красоты. Порядковая нумерация «1, 2, 3 без пропусков» — задача запросов и отчётов, о них пойдёт речь в блоке B.

Подготовка базы к первому запросу: полный маршрут со стартовым комплектом

Выше вы создали базу и таблицу Categories вручную — это навык конструктора, он понадобится в модуле 02. Но чтобы первый SQL-запрос (ниже, в разделе «SQL-код и разбор по строкам») сразу заработал, в базе должна быть ещё и таблица Customers — вместе с остальными таблицами ShopData. Ниже — полный маршрут подготовки «от пустой папки до первого запроса». Он один-в-один повторяет страницу «Начало работы»: там же интерактивный чек-лист готовности, а детальный чек-лист импорта с решениями ошибок — в файле starter-data/import-checklist.md.

Если вы уже импортировали starter-data

Тем, кто прошёл страницу «Начало работы» и импортировал шесть CSV, шаги 6–11 демонстрации выше (создание Categories вручную) выполнять не нужно — таблица уже есть с теми же пятью строками. Откройте Categories в конструкторе и сверьте поля по шагам 7–9: это тот же навык без риска дубля («Таблица с именем Categories уже существует»).

1. Файлы для скачивания. Из репозитория курса — каталог starter-data/: categories.csv, products.csv, customers.csv, employees.csv, orders.csv, order-details.csv. Kaggle и регистрация не нужны: комплект содержит те же данные, на которых выверены все контрольные числа курса. Полный датасет Olist подключается в модуле 04, для этого маршрута он не требуется.

2. Рабочая папка. Создайте C:\Courses\ShopData\ с подпапками import\ (сюда ложатся шесть CSV), base\, export\, backup\. Путь — без кириллицы и пробелов, не на сетевом диске и не в OneDrive.

3. Новая база и её имя. Access → «Пустая база данных» → имя ShopData.accdb → папка base\ → «Создать». Если вы уже создали базу в демонстрации выше (шаги 2–4), это тот же файл — второй раз создавать не нужно; заготовку «Таблица1» закройте без сохранения.

4. Доверенное расположение. Файл → Параметры → Центр управления безопасностью → Параметры центра… → Доверенные расположения → добавить C:\Courses\ShopData\ — иначе Access заблокирует часть мастеров, а позже макросы модуля 11.

5. Импорт каждого файла. Внешние данные → Новый источник данных → Из файла → Текстовый файл → «Импортировать в новую таблицу». Порядок: categories → products → customers → employees → orders → order-details. Разделитель — запятая, кодировка — Юникод (UTF-8), в «Дополнительно…» порядок дат — ГМД (файлы хранят даты как 2017-03-15). Для order-details.csv исправьте предложенное имя таблицы на OrderDetails.

Файл → таблицаСтрокКлючТипы, за которыми следим

products.csv → Products8ProductIDUnitPrice — Денежный; WeightG — Числовой

6. Какие таблицы должны получиться. Шесть таблиц с точными именами из колонки «таблица» — они появятся в области навигации. Седьмая (Calendar) будет создана в модуле 04, здесь она не нужна.

7. Связи. Работа с базами данных → Схема данных: перетащите поля и включите «Обеспечение целостности данных» для пяти пар — Categories→Products (CategoryID), Customers→Orders (CustomerID), Employees→Orders (ManagerID), Orders→OrderDetails (OrderID, + каскадное удаление), Products→OrderDetails (ProductID). Подробный разбор — модуль 03; здесь важно получить линии «1—М».

8. Проверка импорта и количество записей. Откройте каждую таблицу: счётчик записей внизу должен показать 5/8/8/6/12/15, первая строка Customers — C-0001, Ana Ribeiro, 01310, sao paulo, SP, Retail. Целостность проверьте вводом: ManagerID = 9 в Orders должен отклониться.

9. Типичные ошибки этого шага. Даты текстом — повторный импорт с порядком дат ГМД; ZipCodePrefix = 1310 без нуля — тип «Короткий текст (5)»; цены текстом (SUM даёт 0) — решение в import-checklist.md, ошибка № 4; «повторяющиеся значения» при ключе — файл импортирован дважды, удалите таблицу и импортируйте заново.

10. Сохранение и резервная копия. Access сохраняет данные сам, но файл скопируйте: закрытая база base\ShopData.accdb → копия в backup\ShopData_ГГГГ-ММ-ДД.accdb. Готово — ниже можно запускать первый запрос.

Пример из работы аналитика

Представьте типовой понедельник интернет-магазина. В 9:30 директор просит: «В прошлое воскресенье мы запускали акцию, мне нужна сводка по продажам и категориям — и пусть дальше она приходит каждую неделю по пятницам». Аналитик вздыхает: он уже делает такую сводку третий месяц, и каждый раз это ручная работа. Четыре выгрузки из учётной системы — покупатели, заказы, позиции заказов, товары — приходят CSV-файлами. Он открывает Excel, копирует листы в одну книгу, тянуть «ВПР» по шести колонкам, чинит съехавшие форматы дат, пересчитывает сводные таблицы и вычитывает результат на предмет «съехавших» строк. Три часа работы, файл на 180 МБ, и одна ошибочная ячейка способна испортить всю картину.

Проблема не в неумении аналитика, а в инструменте: Excel прекрасен для разового анализа, но каждая повторяемая задача в нём превращается в ручной труд без гарантий. Ровно здесь и начинается Access. Четыре CSV-файла импортируются в четыре таблицы (эта тема раскрывается в модуле 04), между таблицами настраиваются связи и целостность (модули 02–03), расчёт выручки по категориям фиксируется в сохранённом запросе qry_ВыручкаПоКатегориям (модуль 08), а результат печатается отчётом или выгружается в PDF. С этого момента «та же сводка» — это: положить свежие файлы в папку, нажать две кнопки, отправить письмо. Десять минут вместо трёх часов, и цифры совпадают от недели к неделе, потому что считает не человек, а сохранённый запрос.

Что именно мы делаем, чтобы превратить боль в кнопку:

  1. Импортируем четыре CSV в таблицы Customers, Orders, OrderDetails и Products — один раз, с сохранённой спецификацией импорта для повторов.
  2. Проверяем типы и значения: почтовые префиксы остались текстом, цены — денежным типом, даты — датами.
  3. Фиксируем расчёт в запросе: сумма UnitPrice * Quantity по категориям, отменённые заказы исключены.
  4. Закрепляем запуск: сохранённые импорты и кнопка на форме — директорская сводка собирается без участия памяти и терпения аналитика.

SQL-код и разбор по строкам

Первый запрос курса выбирает пять клиентов из Customers. Задача его простая — увидеть, что SQL в Access читается почти как английский, и получить инструмент, который станет рабочей лошадкой курса. Введите запрос так: «Создание → Конструктор запросов», закройте окно «Добавление таблицы», щёлкните правой кнопкой по вкладке запроса и выберите «Режим SQL», затем вставьте текст и выполните его командой «Конструктор → Результаты → Выполнить» (кнопка с красным восклицательным знаком).

SELECT TOP 5 CustomerID, CustomerName, City, Segment
FROM Customers
ORDER BY CustomerID;
  1. SELECT TOP 5 CustomerID, CustomerName, City, Segment — перечисляем возвращаемые поля; TOP 5 ограничивает результат пятью первыми строками. Это диалект Access: в MySQL вместо него пишут LIMIT, и это одна из примет, по которым узнают «чужой» SQL.
  2. FROM Customers — источник данных, таблица клиентов из раздела «Исходные таблицы». Без ORDER BY фраза «первые пять» означала бы «какие пять подряд попались», поэтому третья строка обязательна.
  3. ORDER BY CustomerID; — сортировка по возрастанию идентификатора, от C-0001 к C-0005. Точка с запятой завершает оператор; Access допускает её отсутствие, но дисциплина пунктуации избавит от ошибок при многострочных запросах.

Запомните ощущение «прочитал — и уже понял». В модуле 07 к SELECT…FROM…ORDER BY добавятся условия WHERE, соединения JOIN и особенности диалекта (даты в решётках #2027-01-31#, подстановочный знак * в Like, функция IIF). Пока же важно, что запрос — это сохраняемый объект: назовите его qry_КлиентыТоп5, и он останется в базе вместе с результатом «по кнопке».

Вариант через конструктор запросов

Тот же запрос в Access принято собирать и мышью — конструктор запросов (QBE) визуализирует поля, сортировку и ограничения. Для новичка это быстрый способ не ошибиться в синтаксисе, а затем подсмотреть готовый SQL в режиме SQL. Соберём «пять клиентов» без единого набранного слова:

  1. Откройте «Создание → Конструктор запросов». В окне «Добавление таблицы» дважды щёлкните Customers, затем нажмите «Закрыть». В верхней части бланка появится список полей таблицы.
  2. Двойным щелчком по именам добавьте в бланк поля CustomerID, CustomerName, City, Segment — каждый ляжет в отдельный столбец нижней сетки.
  3. В строке «Сортировка» под CustomerID выберите «По возрастанию».
  4. На вкладке «Конструктор» в группе «Настройка запроса» найдите элемент «Возврат: Все» и задайте значение 5 — это аналог TOP 5.
  5. Нажмите «Выполнить» в группе «Результаты». Сетка результата совпадёт с тем, что вернул ручной SQL из предыдущего раздела.
  6. Переключитесь в режим SQL (правая кнопка по вкладке запроса → «Режим SQL») и сравните: Access сгенерировал ровно тот же текст с SELECT TOP 5.
  7. Сохраните запрос как qry_КлиентыТоп5 (Ctrl+S). Префикс qry_ — часть соглашения об именах курса: по нему сразу видно тип объекта.

Дальше по курсу мы идём тем же двойным ходом: быстрый черновик в конструкторе, аккуратный финал в SQL. Конструктор честно показывает, что делает мышка, а SQL фиксирует результат словами, которые нельзя случайно сдвинуть.

Типичные ошибки

Типичная ошибка

Симптом: новичок открывает Access и заводит один гигантский лист «всё о заказах», как в Excel. Причина: привычка к плоским таблицам: в Excel иначе не умели, а в Access структура не навязывается. Лечение: разделяйте данные по сущностям — клиенты, товары, заказы, позиции; модуль 02 покажет, что каждая сущность заслуживает собственной таблицы, а повторяющиеся колонки — признак будущей боли.

Типичная ошибка

Симптом: месяц выводится в имя столбца: «янв_2017», «фев_2017», а данные сыплются под эти заголовки. Причина: попытка имитировать сводную таблицу прямо в хранилище. Лечение: дата — это значение в поле OrderDate типа «Дата и время», а не имя столбца; повороты данных делаются перекрёстными запросами TRANSFORM…PIVOT (модуль 08).

Типичная ошибка

Симптом: база «на всю компанию» живёт на флешке, и файл пересылают по почте для «одновременной» работы. Причина: незнание модели совместного доступа. Лечение: база лежит на сетевой папке или SharePoint, таблицы отделяются от интерфейса (модуль 14), пользователи получают собственные копии интерфейсного файла; до 10–25 человек это работает без сервера.

Типичная ошибка

Симптом: в SQL-запросе пишут LIMIT 5 или CONCAT(a, b), и Access отвечает синтаксической ошибкой. Причина: привычка к другому диалекту — MySQL или T-SQL. Лечение: Access понимает TOP 5, конкатенацию через &, даты в решётках #2027-01-31# и IIF() вместо CASE; полная шпаргалка диалекта — в модуле 07.

Типичная ошибка

Симптом: пользователь скрывает или удаляет объекты в области навигации, затем решает, что база «опустела», и начинает всё заново. Причина: область навигации фильтрует показ, а «Скрыть» не означает «удалить». Лечение: правая кнопка по заголовку области → «Параметры навигации» → включить показ всех объектов и скрытых; удалённые объекты восстанавливаются из резервной копии базы, поэтому копию файла стоит снимать перед серьёзными изменениями.

Практические советы

Практический совет

Заведите для курса отдельную папку и держите там один файл базы — ShopData.accdb. Access любит «разбрасывать» созданные файлы по недавним папкам, а учебные артефакты (спецификации импорта, экспортные выгрузки) появятся уже в модуле 04. Одна папка — одна база — ноль потерь времени на поиски.

Практический совет

Запомните разницу сохранений: данные в Access записываются сразу при переходе с строки — отдельного «сохранения» строк не существует. Ctrl+S сохраняет структурные изменения (конструктор таблицы, макет формы) и сам файл. Привычка из Excel «нажимать сохранение после каждой правки» здесь избыточна, а вот привычка закрывать Access перед выключением компьютера — полезна.

Практический совет

Настройте область навигации под себя: правая кнопка по её заголовку → «Параметры навигации» → группировка «Тип объекта». Таблицы, запросы, формы и отчёты образуют отдельные секции — по мере роста базы (а в курсе их будет несколько десятков) это экономит минуты каждый день.

Практический совет

Загляните в «Файл → Параметры → Текущая база данных» и включите «Сжимать при закрытии» — файл не будет пухнуть после удаления записей. Там же задайте «Форма просмотра» — стартовую форму приложения; в модуле 09 мы сделаем для неё навигационную форму frm_Панель.

Практический совет

Учите SQL с первого дня, даже если конструктор «и так рисует». Конструктор хорош для черновика и обучения, но повторяемые, параметрические и сложные соединения быстрее и надёжнее фиксировать текстом SQL. Каждый модуль блока B заканчивается разбором SQL — эти куски копятся в личную шпаргалку.

Краткое резюме

Access — это файл-контейнер .accdb, в котором движок ACE обслуживает шесть типов объектов: таблицы хранят, запросы спрашивают, формы вводят, отчёты печатают, макросы и VBA автоматизируют. Access выбирают, когда данных сотни тысяч строк, нужны жёсткие типы, целостность, несколько пользователей и повторяемые отчёты; когда пользователей сотни и данных гигабайты — это уже серверная СУБД, к которой Access может подключаться интерфейсом. Вы создали первую таблицу Categories с ключом-счётчиком, выполнили SELECT TOP 5 в режиме SQL и собрали тот же запрос мышью, сверив результат построчно. Следующий модуль — «Проектирование таблиц и типы данных»: мы разберём, почему почтовый префикс «01310» обязан быть текстом, какую цену платят за деньги в числовом поле и как плоский лист Excel превращается в семь нормализованных таблиц ShopData.
