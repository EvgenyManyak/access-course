## [1.1.8] — 2026-10-16

### Исправлено

- **Модуль 13 «Импорт и экспорт»: инструкции приведены к русскоязычному интерфейсу Access и фактическим возможностям мастера.**
  Шаг 10 демонстрации: запуск сохранённой операции описан через официальную макрокоманду
  «ВыполнитьСохраненныйИмпортЭкспорт» (RunSavedImportExport) с точным названием аргумента
  «Имя сохраненного определения импорта или экспорта» — в русскоязычном интерфейсе
  макрокоманда в списке не ищется по английскому имени; явно отмечено, что макрокоманда
  появилась в Access 2010 (в Access 2007 операция запускается кнопкой «Выполнить» из панели
  сохранённых операций) и доступна только в доверенной базе («Включить содержимое»).
  То же имя подставлено в цели обучения, теорию, таблицу кейса, чек-лист, задание I05
  (план, критерии, эталонное решение), тест и резюме — английский вариант сохранён только
  в VBA-контексте (DoCmd.RunSavedImportExport), где английские имена корректны.
  Шаг 7 демонстрации: инструкция больше не требует найти в списке пункт «Windows (ANSI)» —
  кодировка описана как вариант Windows по умолчанию в окне «Дополнительно…» (подписи
  вариантов зависят от версии Access; ориентир — Windows, а не MS-DOS/Юникод); аналог в
  чек-листе (m13:2), задании I05 и эталонном решении. Настройки разделителя, ограничителя
  текста и «Включить имена полей в первой строке» перенесены на шаг мастера, где они
  фактически находятся.
  Шаг 3 демонстрации: описана зависимость флажков диалога экспорта в Excel — «Открыть
  целевой файл после завершения операции копирования» доступен только при включённом
  «Экспортировать данные с форматированием и разметкой»; в шаге 6 уточнено, что в диалоге
  текстового экспорта такого флажка нет (настройка применима только к экспорту в Excel).
- **Рис. 1 (схема каналов обмена) перерисована без наложений подписей.** Стрелки сделаны
  горизонтальными, подписи центрированы и вынесены в свободные зоны между блоками
  (viewBox 760×250 → 820×250) — подписи «импорт/связь», «TransferSpreadsheet»,
  «TransferText», «OutputTo acFormatPDF» больше не заходят на рамки и читаются целиком.
- **Задание I05 «Экспорт по кнопке»: шаг 3 переписан в конкретный план** — два способа
  получить входящий файл (готовый starter-data/new_customers.csv или сборка своими руками
  через запрос qry_ЭкспортПокупателей), параметры выгрузки и проверка результата в Блокноте.
  В эталонном решении подробно разобрано создание запроса qry_ЭкспортПокупателей: источник
  (Customers), состав и порядок полей под заголовок CSV, отсутствие критериев, сортировка,
  «Возврат» = 3 и готовый SQL с TOP 3. Исправлен флажок мастера импорта: «Первая строка
  содержит названия столбцов» вместо ошибочного «Первый столбец содержит заголовки»
  (термин согласован с модулем 04).
- **Исправлена ситуация «CSV импортируется одной строкой/в один столбец»**: добавлена
  типичная ошибка с причинами (несовпадение разделителя, окончания строк старого Mac,

## [1.1.7] — 2026-10-14

### Исправлено

- **Модуль 12 «VBA на прикладном уровне»: эталонное решение задания V02 переведено на запуск сохранённой спецификации импорта.**
  Код кнопки btnImportCsv_Click вызывал DoCmd.TransferText acImportDelim со ссылкой на
  «spec_ИмпортКлиентов». В описанном сценарии этот вариант не работает: спецификация создана
  в модуле 04 флажком «Сохранить шаги импорта», то есть является сохранённой операцией
  импорта, а не классической спецификацией TransferText. В эталонном решении вызов заменён
  на DoCmd.RunSavedImportExport "spec_ИмпортКлиентов" — и в базовой процедуре btnImportCsv_Click,
  и в её усложнённом варианте (шаг 4 раздела «Эталонное решение» самостоятельной работы):
  путь к файлу, признак заголовков и все остальные настройки теперь хранит сама операция,
  поэтому в коде они не передаются. Модификация под другой файл (btnImportProducts_Click,
  шаг 3) намеренно оставлена на классическом DoCmd.TransferText со спецификацией
  «spec_ИмпортТоваров» — как контраст двух способов вызова импорта.

  работы аналитика, критерии проверки; точное имя сохранённой спецификации spec_ИмпортКлиентов

- **Модуль 11 «Макросы Access»: инструкции и рисунки приведены к русскоязычному интерфейсу Access 2007–2016.**
  Пошаговая демонстрация: в шаге 2 у OpenForm аргумент «Режим данных» описан с реальным

  доступной группы «Поток программ» в «Каталоге действий».
- **Задание V01 «Макрос экспорт месяца», шаг 4: экспорт в файл заменён на отправку объекта БД письмом.**
  В русской версии Access 2007–2016 экспорт объекта из макроса сценария недоступен —
  вместо него используется действие «ОтправитьОбъектБД»: Тип объекта — Запрос, Имя объекта —
  qry_ВыручкаПоКатегориям, Формат вывода — Книга Excel (*.xlsx), Кому — адрес получателя,
  Тема — Выручка по категориям, «Изменение сообщения» — Да (письмо открывается для проверки
  перед отправкой), «Файл шаблона» — пусто. Из сценария убраны несуществующие для него
  названия: Output To, «Файл», «Экспорт», «Автозапуск». Под новое действие сведены цель
  задания, подготовительный шаг (проверка почтовой программы), ожидаемый результат
  (письмо с книгой Excel во вложении), критерии оценки, подсказка и эталонное решение.
- **Рис. 1 (diagrams/macro-flow.svg) перерисован под макрос AutoExec из демонстрации.**
  Прежняя схема изображала старый сценарий с OutputTo, путём export\выручка_…, аргументом
  «Автозапуск» и параметром «Месяц», которых в исправленном модуле больше нет. Новая схема
  показывает последовательность OpenForm → ОкноСообщения → блок «Если» с понедельничным
  напоминанием и ветку «Иначе»; надписи в ромбе условия центрированы (text-anchor="middle").
  В таблице действий пример для OutputTo отвязан от сценария выручки (теперь — сохранение
  rpt_Топ10Товаров в PDF: файловая выгрузка остаётся реальным действием, но к заданию V01
  не относится).

- **Модуль 07 «Access SQL и соединения таблиц»: SELF-JOIN (Запрос 5) не работал на стартовом комплекте.**
  В starter-data/employees.csv нет поля ManagerID — запрос «кто кому подчиняется»
  заканчивался окном «Введите значение параметра ManagerID». Проблема теперь названа

  через Конструктор), заполнение подчинения двумя запросами
  `UPDATE Employees SET ManagerID = 1 WHERE EmployeeID In (2, 4);` и
  `SET ManagerID = 3 WHERE EmployeeID In (5, 6);` — руководители верхнего уровня
  (Ana Souza, Maria Oliveira) остаются с NULL; контрольный SELECT даёт эталон из
  6 строк. Сам SELF-JOIN приведён к рабочему виду `e1 LEFT JOIN e2 ON
  e1.ManagerID = e2.EmployeeID`, в разборе объяснено, почему INNER JOIN потерял бы
  обе строки вершины (NULL не совпадает ни с чем).

### Исправлено

- **Мобильное меню (бургер ☰) не раскрывалось по нажатию на сенсорном экране.**
  Причины: (1) открытая панель сайдбара (z-index 100) и затемняющий фон (z-index 90)
  перекрывали кнопку в шапке (z-index 80) — повторное и часть первых нажатий
  приходились на панель/фон, а не на кнопку; (2) состояние держалось только на
  классе body.nav-open без классов состояния на кнопке и меню, без ARIA-атрибутов
  и без резервного обработчика на самой кнопке; (3) `.icon-btn { display:inline-flex }`
  в каскаде перебивал `.topbar__burger { display:none }` — бургер был виден и на
  десктопе, где меню и так открыто.

### Изменено

- `js/app.js`: кнопке меню задан эталонный id `menuToggle` + `aria-expanded`,
  `aria-controls="courseMenu"`, динамический `aria-label`; сайдбар получил
  id `courseMenu` и управление `aria-hidden`.
- `js/navigation.js`: единая машина состояний меню — openMenu/closeMenu/toggleMenu
  (`.is-open` на меню, `.is-active` на кнопке, `body.nav-open` для фона и блокировки
  прокрутки); прямой обработчик click на кнопке с stopPropagation (делегирование
  сохранено как резерв); закрытие по клику вне меню, по Escape с возвратом фокуса
  на кнопку, по выбору пункта; сброс состояния при переходе к ширине > 1024px;
  диагностический console.error при отсутствии элементов.
- `css/styles.css`: `.topbar .topbar__burger { display:none }` повышенной
  специфичности — бургер снова скрыт на десктопе.
- `css/responsive.css`: слои фон (90) < шапка (95) < панель (100) < бургер (1100);
  панель раскрывается под шапкой (top: var(--topbar-h)); плавная анимация
  transform + visibility (0.25s) и fade фона; `touch-action: manipulation` и
  подсветка нажатия убраны; видимое состояние `.topbar__burger.is-active`.
- Пересобраны standalone.html и access-course-project.zip (80 файлов).

## [1.0.0] — 2026-09-15

Первый публичный релиз учебника.

### Добавлено

- **Курс:** 15 модулей Microsoft Access 2007–2016 (единая структура из 17 секций),
  80 академических часов, 20 практических заданий E01–V02 на сквозном датасете
  ShopData (основа — Kaggle Olist Brazilian E-commerce), итоговый проект
  с 20-пунктовым чек-листом сдачи.
- **Интерфейс:** сайдбар с оглавлением модуля и scrollspy, кликабельное оглавление,
  «Назад/Далее», индикатор прогресса, полнотекстовый поиск по всему курсу,
  светлая и тёмная темы, раскрывающиеся решения (details), блоки «Важно» /
  «Типичная ошибка» / «Практический совет», интерактивные чек-листы,
  тесты 6–8 вопросов с пояснениями и порогом 80%, клавиатурная навигация
  (← → / Ctrl+K / Esc), адаптивная вёрстка, поддержка кириллицы.
- **Экспорт (8 действий):** печать/PDF с титульной страницей и оглавлением,
  скачивание HTML раздела, экспорт модуля и всего курса в Markdown,
  экспорт модуля и всего курса в TXT, копирование раздела и всего курса
  в буфер обмена; экспорт «весь курс» работает офлайн за счёт зашитого
  кэша содержимого (COURSE_CACHE в js/export.js).
- **Данные:** каталог datasets/ — кликабельные ссылки Kaggle с лицензиями
  и датами проверки (Olist — основной; Superstore и Online Retail —
  альтернативы; непроверенная ссылка помечена TODO: VERIFY DATASET URL),
  словарь данных, инструкции импорта (3 пути, включая мини-датасет без Kaggle).
- **Код-примеры:** 6 файлов Access SQL (выборки, соединения, агрегаты,
  параметры, перекрёстные, action-запросы) и 3 файла VBA + README
  (экспорт, импорт и переподключение связанных таблиц, события форм).
- **Схемы:** 4 SVG — ER-диаграмма ShopData, поток данных CSV→отчёт,
  разделение BE/FE, последовательность макроса.
- **Документация:** программа курса, чек-лист студента, руководство
  преподавателя, гайд по тестированию (18 пунктов).
- **Инфраструктура:** standalone.html (весь курс в одном файле), скрипты
  build-zip.ps1 и build-zip.sh, .gitignore, LICENSE (MIT + примечания
  о датасетах), README (18 разделов), favicon и логотип.

### Особенности реализации

- Чистые HTML + CSS + JavaScript, без зависимостей и сборочных инструментов;
  работает по file:// и на GitHub Pages.
- Прогресс, результаты тестов и чек-листы — в localStorage (ключи ac.*).
- Подсветка SQL/VBA — собственный токенайзер (без внешних библиотек).
- Версионирование контента: манифест модулей — js/app.js (AC.MANIFEST);
  добавление модуля — копия страницы + запись в манифест.

### Известные ограничения

- Прогресс не синхронизируется между устройствами; поиск ищет по кэшу,
  который нужно пересобирать после правок модулей; номера страниц в PDF
  проставляет браузер (опция «Колонтитулы»); DOCX/XLSX в браузере не
  генерируются (в панели экспорта даны инструкции по конвертации).
